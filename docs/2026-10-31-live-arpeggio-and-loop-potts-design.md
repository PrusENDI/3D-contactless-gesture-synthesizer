# 分阶段设计（rev4）：阶段 0 波表发声 → 阶段 1 LIVE 琶音 → 阶段 2 LOOP 变分

状态：**待批准**（批准前不改 RTL）
仓库：`mgc3130_clean`（master @ `45ca44f`）
取代：rev3（同文件）。rev4 按"先最基础链路"重排为三个阶段，阶段之间不互相依赖。

## 0. 阶段划分

| 阶段 | 交付 | 依赖 | 状态 |
| --- | --- | --- | --- |
| **0 波表发声** | 一张表、一个音、正确音高、可抓波形 | 无 | **本阶段** |
| 1 LIVE 琶音 | 每 tick 一音，音高跟 y | 阶段 0 的音高链路 + tick | 未开始 |
| 2 LOOP 变分 | 定长轮廓 → Potts → 循环播放 | 阶段 1（同一音高坐标） | 未开始 |

阶段 0 故意**不碰** tick、Potts、琶音、loop store——它是整个系统唯一能被单点验证的一环。

## 1. 阶段 0：单声部波表发声

### 1.1 目标

音色由波表决定：音符只决定相位累加速率，波形完全来自上位机下发的 1024 点表。

```
上位机：划动 → 时间归一化 → 重采样 1024 → 限带 32 谐波 → UART 下发
板上：  note → increment → phase += increment → index = phase[31:22] → 查表 → I2S
```

### 1.2 现状与缺口

| 已有 | 缺 |
| --- | --- |
| 上传链路：3 表（A/B/C）× 1024×16，shadow/active 双 bank，CRC16/CCITT-FALSE，三方版本匹配，APPLY 只在 idle/loop 边界切换（[v2_wavetable_loader.sv](mgc3130_clean/rtl/v2_wavetable_loader.sv)，`52009f8` 板上读回连过三轮） | **声部路径不读表** |
| `v2_wt_playback` 能走到表（`WT_PLAY` 模式），但相位固定 `+65536`/采样 = 46.875 Hz，是抓波形用的测试通路（[v2_wt_playback.sv:30](mgc3130_clean/rtl/v2_wt_playback.sv#L30)） | 相位增量与音符无关 |
| `v2_note_increment_rom` 已有 8 个五声音级的 32 bit 增量，语义正是 `f/48000 × 2^32`（A4=440 Hz → 39,370,534） | 没接到播放器上 |

**结论：缺的只是"把音符增量接到相位累加器"。** 这是最小的可交付。

### 1.3 改动（三处，都很小）

**改动 1 — `v2_wt_playback`：相位宽度 26 → 32，增量变成输入**

```
现在：phase <= phase + 26'd65536;        index = phase[25:16]   // 固定 46.875 Hz
改为：phase <= phase + increment;         index = phase[31:22]   // 1024 点/周期
```

`increment` 由 `v2_note_increment_rom` 给出（复用它，不新建表）。8 个音级的增量已经对得上：

| 音 | increment | 实测频率 | 周期（48 kHz） |
| --- | --- | --- | --- |
| 55 G3 | 17,537,476 | 195.99 Hz | 244.9 采样 |
| 64 E4 | 29,494,575 | 329.63 Hz | 145.6 采样 |
| 69 A4 | 39,370,534 | 440.00 Hz | 109.09 采样 |
| 72 C5 | 46,819,719 | 523.25 Hz | 91.8 采样 |

**改动 2 — 测试音符来源：`V2_CSR_THRESHOLDS(0x30)` 的 `[7:0]`**

- `0` = 保持现在的 46.875 Hz 固定播放（**旧验收用例不受影响**）；
- 非 0 = 当作 MIDI 音符（默认建议 69），只在 `WT_PLAY` 模式生效。

用这个寄存器的理由：不新增地址、不改契约；`[31:16]` 已计划给阶段 2 的 λ。

**改动 3 — 表选择：`WT_SELECT` 的低 2 位选 A/B/C**（默认 0 = A）

不动：32 声部引擎、FX、tick、Potts、loop store。

### 1.4 表内容契约（上位机侧）

| 项 | 规定 |
| --- | --- |
| 点数 | 1024，正好一个周期 |
| 格式 | int16，首点 = 相位 0（保证接缝连续） |
| 直流 | 去 DC（均值 ≈ 0） |
| 峰值 | ≤ 0.9 FS，避免削波 |
| 限带 | 32 次谐波 |
| 传输 | 分块写 `WT_INDEX/WT_DATA`，写 `WT_CRC`，再 `WT_APPLY`（沿用现有协议） |

混叠检查：本音域最高 C5 = 523.25 Hz，`32 × 523.25 = 16.7 kHz < 24 kHz`（Nyquist），
所以在 G3..C5 内 32 谐波不会混叠。更高音需要"按音高降谐波数"（规格 §12.2），本阶段不做。

### 1.5 验收（全部可机器检查）

1. **音高正确**：上传 1024 点正弦 → APPLY → `WT_PLAY`、`THRESHOLDS[7:0]=69` → GAO 抓 I2S 数据，
   周期 = 109.09 采样 ±0.5%。
2. **音高表**：换成 55 / 64 / 72，周期分别为 244.9 / 145.6 / 91.8 采样 ±0.5%。
3. **真的在读表**：A 表与 B 表分别上传不同波形，切换 `WT_SELECT` 后抓到的波形不同——这条排除
   "其实还是内部振荡器"的可能。
4. **切换无爆音**：idle 时 APPLY，切换前后相邻样本差 < 10% FS。
5. **旧路径不回归**：`THRESHOLDS[7:0]=0` 时仍是 46.875 Hz，原有 WT_PLAY 验收用例照旧通过。

### 1.6 资源与风险

改动只到相位器宽度（26→32，+6 个触发器）与一个 ROM 复用：**0 DSP、0 BSRAM、约 +10 LUT**。

风险：
- 索引截断（不做插值）带来约 −60 dB 的量化噪声；若听感不接受，阶段 1 再加线性插值（约 150 LUT）。
- 表峰值不统一会导致响度不一致——由增益解决，不改表。
- `increment = 0`（非五声音级）会静音：只有 8 个音级可用，这是现成 ROM 的限制，本阶段接受。

### 1.7 上行链路与上位机解算器

**上行已存在**：遥测帧里带 `cursor_x/y/z`（各 16 bit），22 字节/帧，速率由 `TLM_CONTROL` 控制
（[mgc3130_v2_top.sv:974](mgc3130_clean/rtl/mgc3130_v2_top.sv#L974)）。PC 只需把这些帧录成 JSONL。

**关键好处**：弧长相位只用位置、不用时间，所以 `capture_tick` 现在是 `sample_index[7:0]`
（5.3 ms 回绕）这件事**不影响阶段 0**——只要帧的顺序对（`capture_sequence`），解算就是确定的。

```
python tools/wavetable_from_capture.py capture.jsonl --phase arc --axis y --out lead.bin
```

| 步骤 | 规定 |
| --- | --- |
| 平滑 | 每轴 5 帧中值 + IIR 0.35（**先平滑再积分**，与 PC 参考一致） |
| 弧长 | `ds = |Δ(x,y)|`；`ds < 40 counts` 记 0（≈3 倍传感器抖动，抑制静止漂移） |
| 相位 | `φ_i = s_i / s_N` |
| 幅度 | `a = y`（音高轴）；按 φ 线性插值重采样到 1024 点 |
| 后处理 | 去 DC（`|mean| < 1 LSB`）、峰值归一 0.9 FS、限带 32 谐波 |
| 输出 | 1024 × int16，首点 = φ=0 |

`--phase` 三选一：`arc`（默认；速度无关，形状被斜率改写）、`time`（规格原方案）、
`x`（形状保真，要求 x 单调）。

**解算器验收**：

1. 同一份 capture 跑两次 → 表逐字节一致；
2. 表长 1024、`|mean| < 1`、峰值 = 0.9 FS ±1 LSB；
3. 32 次以上谐波能量 < −60 dBFS（DFT 自检）；
4. 一段 1 Hz、x 单调的正弦手势用 `--phase x` 解算，重建波形与输入相关性 > 0.99。

## 2. 阶段 1：LIVE 步进琶音（摘要）

- 每 `tick_pulse` 发 `NOTE_OFF(上一个) + NOTE_ON(当前 y 的最近邻音级)`，音高相同也重发（步进琶音的"重复敲"）。
- 需要新的 `v2_tick_gen`：`samples_per_tick = 720000/BPM`，BPM 60..240、默认 120（契约），
  120 BPM = 125 ms/tick、8 音/秒；写入 BPM 时重置 tick。
- 音高坐标：Y 全量程、1 半音 = 3855 counts、最近邻（与 PC 一致）。
- 删除：左边界 arming、`edge_cross`、死的 `note_change_ok`、每帧 `EV_CONTROL`。
- NOTE_OFF 必须能在 gate 回落时发出（现状 `bad_frame` 把它挡死，会卡音），加 2 s 超时兜底。
- 音高到频率仍用 `v2_note_increment_rom`（同一套增量）。
- 验收：128 tick 内 128 个 `NOTE_ON`，间隔恒为 1 tick；斜坡上行音高单调。

## 3. 阶段 2：LOOP 定长轮廓 + Potts（摘要）

- RECORD 只录 **128 tick 的 y**（128×16，1 BSRAM），不录事件、不发声；录满置 `contour_full`。
- COMMIT：`PREPARE → CLEAR_TRACK(lead) → Potts → 写 shadow（≤32 事件）→ COMMIT_REQUEST`，
  在 loop 边界翻 bank。
- Potts：8 音级、误差 `((y − c_k) >> 6)²`、λ 放 `THRESHOLDS[31:16]`、`HORIZON` 形态待定。
- LIVE 事件不入 store（每轨只有 32 槽）。

### 阶段 2 仍待你定的三件事

1. **Potts 形态**：5 块分块（+80 LUT，接缝要验收）还是 `HORIZON=128` 一次跑完（+1 DPB lane）？
2. **PC 金标准**：`v2_potts_reference.py`（5 音级）还是 `synthwave_loop.py`（8 音级）？
   改全量程会破 `mgc3130_uart` 现有测试，允许改老仓库吗？
3. **事件表要不要 CSR 可读**：现在没有读口，加窗口未计入预算；或接受 GAO + 仿真作证据。

## 4. 共同约束

- 验收位流用 `PRESERVE_LOOP_PLANE=0 / PRESERVE_POTTS_PLANE=0`（现在是探针触发，CSR 命令不会启动 Potts）。
- 每层验证留产出物（`gate.py` / `sim.py` / `synth.py` / `host/*.ps1` / `gao_capture.py`）。
- 位流身份（sha256 + commit）与未跑项必须记录。

## 5. 我替你定下的

1. 阶段 0 用 `THRESHOLDS[7:0]` 当测试音符，`0` 保持旧行为。
2. 音符→频率复用 `v2_note_increment_rom`，相位宽度 32 bit，`index = phase[31:22]`。
3. 表由上位机计算并按 §1.4 契约下发；板上不做限带。
4. 分阶段验收，阶段 0 的 5 条判据不与后面耦合。
5. **相位 = 归一化弧长**（默认），幅度 = y；弧长死区 40 counts。
6. 相位方式做成 PC 侧参数（`arc|time|x`），换方式不需要改板子。
