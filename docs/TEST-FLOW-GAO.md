## 16. 触发机制的实测结论（2026-10-30 收尾）

试了三种 MatchUnit 配置，全部重建 + 重烧 + 重抓：

| 配置 | 结果 |
| --- | --- |
| 无 `<MatchUnits>` | 静态窗口（强制超时） |
| `match_type="1" value0="1"`（vendor `.rao` 风格） | 静态窗口 |
| `match_type="0" value0="1"`（GUI `.gao` 风格） | 静态窗口 |

**关键发现（时间证据）**：`gao_sh` 在 **APPLY 发出之前**就已返回并写好 CSV
（抓取命令 <1 s 完成，而触发命令 6 s 后才发）。也就是：

> `gao_sh` 不是"武装后等待触发"，而是**读取 AO 缓冲区的当前快照**就退出。
> 缓冲区里是空闲态，说明触发条件在抓取之前从未匹配过。

因此 `-force_trigger_timeout` 只在会话被保持时才有意义；一次性调用根本等不到事件。

### 16.1 由此确定的下一步

1. **用 GUI 验证一次触发**（最便宜）：`gao_analyzer.exe` 打开 `gao/apply.rao`，
