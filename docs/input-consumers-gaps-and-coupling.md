## 10. 待机静音保证 + 与 Python 参考实现的差异（2026-10-31）

### 10.1 待机静音（已修）

现象：不运行上位机时仍有持续音。
原因不是"设计自启动"，而是**上一次脚本把模式留在 LIVE**、且音符从未释放。

修复：**不在 LIVE/PLAY 时把声音引擎按住复位**

```verilog
wire voice_rst_n = rst_sys_n && (mode_live || mode_play);
v2_voice_engine_banked ... .rst_n(voice_rst_n)
```

烧录后（位流 `35F5147B…668F`）实测：`MODE=0`，声音引擎处于复位 → **任何残留音符都不可能发声**。
（`active=1/gate=1` 是规则引擎的内部状态，不等于发声。）

### 10.2 与 `tools/synthwave_loop.py` 的关键差异

| 维度 | Python 参考（`compile_lead`） | 当前 RTL |
| --- | --- | --- |
| 出音时机 | **只在锚点**：move / hold / turn / apex / valley / release | 每次音高变化就 revoice（连续跟踪） |
| 锚点之间 | **不出音**（rest），rest 也有明确长度（如 70 tick） | 一直保持上一个音 |
| 音符时长 | 由"段长"决定（hover=静音，段落=音长） | 无段概念，随下一次变化覆盖 |
| 音高来源 | 手位 y → 55..72 → 五声量化（已对齐） | 已按同一公式重写 ✓ |
| 抖动抑制 | `min_segment`、驻留时间、滞回 | 只有 `MIN_EVENT_TICKS=4` + 五声滞回 |

**结论：音高映射已一致，但"什么时候出音、出多久"完全不同。**
这正是"听起来不像设计"的根因——当前 RTL 是一个连续跟踪器，参考实现是**姿态锚点驱动的音符序列**。

### 10.3 对齐方案（下一步）

1. **锚点检测**（在光标帧流上）：
   - `apex/valley`：`dy` 符号翻转且幅度超过阈值；
   - `turn`：`dx` 符号翻转；
   - `hold`：连续 N 帧位移小于阈值；
   - `release`：`cursor_engaged` 下降沿；
   - `move`：持续位移超过阈值。
2. **段化**：锚点之间构成一段，段长 = 音符时长；段间按参考实现插入 rest；
3. **去抖**：`min_segment` 与驻留时间，避免"机关枪"式重复音；
4. **仿真先行**：用 Python 参考对同一段轨迹生成期望事件序列，作为 RTL 的逐事件回归。
