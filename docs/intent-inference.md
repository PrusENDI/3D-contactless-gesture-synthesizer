# 实时意图推断：音区 / 节奏型 / 旋律型

> 2026-11-04。从光标流实时判断"手想在做什么"，**全程因果**（只用已经发生的样本），
> 输出三个标签 + 置信度。实现 `host/v2_console/intent.py`，入口 `host/intent_live.py`。

## 为什么是这三个标签

| 标签 | 回答的问题 | 用途 |
| --- | --- | --- |
| **音区** `low/mid/high` | 这句在低、中、高哪一段 | 换音色、改八度、选琶音范围 |
| **节奏型** `even/dotted/accelerating/slowing/free` | 手是匀着走、还是 2:1、还是越走越快 | 对齐琶音步长、改鼓点密度 |
| **旋律型** `ascending/descending/arch/valley/wave` + `stepwise/arpeggio` | 轮廓形状 + 音程大小 | 选走位模式、建议下一句 |

## 延迟预算（用户可接受"一点延时"）

| 事件 | 生效延迟 | 依据 |
| --- | --- | --- |
| 换音 | **约 15 ms** @200 Hz | 新档位连续 3 个样本才认（`confirm=3`） |
| 音区 | 约 **0.6 s** | 取最近 600 ms 的中位数，抗手抖 |
| 节奏型 | 约 **2–3 个音**（300–450 ms） | 需要 ≥3 个 IOI |
| 旋律型 | 约 **3–4 个音**（450–600 ms） | 需要 ≥4 个音才有转折点 |
| 端到端 | **≤ 1 s** | 加上 FTDI 16 ms 批量 + UART 传输 |

没有任何"未来样本"被使用，所以延迟就是窗口长度，不会随缓冲增长。

## 数据从哪来

板子的遥测帧（22 字节）已经带 `x / y / z / note / tick`。周期由 `0x80` 决定：

```
0x80 = (周期采样数 << 16) | 1      # 48000 / 周期 = 帧率
200 Hz → 240 个采样 → 0x00F00001
500 Hz → 96         → 0x00600001
```

1 Mbaud 下 200 Hz 只占约 4.4% 带宽，500 Hz 约 11%。FTDI 的 16 ms 定时器会把帧按批送来，
所以时间戳用到达时间，抖动 ±16 ms——对 125 ms 的音符尺度够用。

## 判定规则（v1，全部是规则不是学习）

1. **换音**：`y` 落进哪个音阶档（7 个边界）变了，且新档连续 3 个样本 → 一个音。
   两个音间隔 < 60 ms 合并（同一次手势）。静止的手算**一个持续音**，不算旋律。
2. **音区**：最近 600 ms `y` 的中位数落在量程的三等分里。用中位数而不是均值，
   一次 50 ms 的手抖不会把音区带偏。
3. **节奏型**：音的间隔（IOI）序列 →
   - 变异系数 < 0.20 → `even`；
   - 间隔只分成两簇且比值在 1.6–2.6 之间、中间没有值 → `dotted`；
   - IOI 对序号做最小二乘，|斜率| 归一化后 > 0.15 且 R² > 0.5 → `accelerating` / `slowing`；
   - 都不满足 → `free`（**不下结论**比乱判重要）。
4. **旋律型**：音级序列的差分 →
   - 全正/全负 → `ascending` / `descending`；
   - 只有一个转折点 → `arch` / `valley`；
   - 多个转折 → `wave`；
   - 平均音程 ≤1.2 级 → `stepwise`，≥2 级 → `arpeggio`。

## 已知限制

1. **欠定**：同一段轨迹可以解释成"慢速大跳"或"快速级进"。所以输出带 `confidence`，
   调用方应该**只在置信度高时动作**（≤0.3 时建议不动）。
2. **还没闭环**：v1 只"观察并打印"，不写任何寄存器（唯一写的是 `0x80` 开关）。
   要把结论接回合成器（例如自动选琶音走位），是下一步。
3. **抖动来源**：FTDI 的 16 ms 批量、传感器 ~85–165 fps，都会让 IOI 有 ±16 ms 噪声；
   所以 `even` 的阈值取 0.20 而不是 0.05。
4. 半径外的动作（x/z）还没进模型；`z` 适合做力度/音量，`x` 适合做速度。
