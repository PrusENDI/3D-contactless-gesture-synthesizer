## 11. 输入坐标约定修正（2026-10-31）：极值跳变与"不 1:1"的根因

### 11.1 症状

- PC 轨迹上常见 **上下极值跳变**；
- 与 PC 版设计**不是 1:1 绝对映射**。

### 11.2 根因：把 **signed** 的传感器坐标当成 unsigned 再减 32768

传感器（GestIC）的 x/y/z 是 **signed 16 位**；PC 端 `mgc3130_receiver.cpp` 直接用
`position.x/y/z`（int16），`project_sample` 只减去校准中性点，**没有 32768 偏置**。

而 FPGA 侧原来写的是：

```verilog
v2_raw_x <= $signed({1'b0, x_position}) - 17'sd32768;   // 错：先零扩展再减
```

效果：`-1`（0xFFFF）→ `65535 - 32768 = +32767` → **符号翻转并顶到最大极值**，
这正是"极值跳变"的来源，也是"与 PC 不 1:1"的来源。

### 11.3 修正

| 位置 | 改动 |
| --- | --- |
| `mgc3130_input_latch.sv:57-58` | `v2_raw_x <= {{1{x_position[15]}}, x_position};`（**符号扩展**，不再减 32768） |
| `v2_cursor_filter_timed.sv:232/241` | 输入装载时 `in_x <= frame_x + 32768;`（把 signed 原始值换到 0..65535 居中坐标，与 `map_note` 的区间一致） |

坐标约定从此统一：

```
传感器 signed 16 位  →  校准（signed）  →  +32768  →  光标 0..65535（中心 32768）
```

### 11.4 板上验证（位流 `A40E127D…44F0`）

```
const=0x5A5A0003
cx=0x8000 (32768)  cy=0x8000 (32768)  z=0
（连续 6 次读数一致，不再出现 0x7FFF/0xFFFF 这类极值钉住）
```

### 11.5 说明：还不是严格的"1:1 绝对映射"

PC 侧还有**校准中性点/旋转/增益**（`project_sample` 的 offset/rotation/scale）。
FPGA 目前把中性点固定为 0、旋转为单位阵、增益为 1——即"原始坐标系"。
要做到与 PC 完全一致，需要把 `CalibrationProfile` 的数值通过 CSR 下发；
这一步在 spec 里属于"每次录音调 `gestic_force_calibration()`"的离线部分。
