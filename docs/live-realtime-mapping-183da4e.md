## 13. 按 SDK 手册复审 reader 的结论（2026-10-31）

依据：`GestIC SDK 1.2.0` 的 `api/include/gestic_api.h` 与 `api/src/stream.c`。

### 13.1 已经对的部分（与 SDK 逐字段一致）

| 项 | SDK | RTL | 结论 |
| --- | --- | --- | --- |
| 配置字 | `data[4..5]` 小端 | `{frame[5],frame[4]}` | ✅ |
| 可选字段顺序 | DSP 2 → Gesture 4 → Touch 4 → AirWheel 2 → Position 6 → Noise 4 → CIC 4×n | 完全一致 | ✅ |
| `xyz_valid` | `systemInfo` bit0 (`data[7][0]`) | `frame[7][0]` | ✅ |
| x/y/z 端序 | 小端（低字节在前） | `{frame[+1],frame[+0]}` | ✅ |
| touch 存在位 | config bit2 | `parse_output_mask[2]` | ✅ |
| 坐标范围 | **0..65535 无符号** | 已改零扩展、`cursor = raw` | ✅（§12） |
| z 语义 | 0=接触，65535=远 | `Z_ENGAGE=30000`（小于即接合）、`Z_RELEASE=36000` | ✅ 方向一致 |

### 13.2 必须改的（按严重度）

| # | 问题 | SDK 依据 | 后果 |
| --- | --- | --- | --- |
| **P1** | **不检查消息 ID** | `stream.c` 只把 `0x91`(Sensor_Data_Output) 当数据；`0x15`(System_Status) 是状态/错误消息 | 状态消息被当数据解析 → 假坐标、`report_valid` 乱跳 |
| **P2** | **`saturated` 从未赋值** | `systemInfo` bit5 = `Clipping` | 夹顶帧不会被判非法，坐标跳变被当成真实移动 |
| **P3** | **未发送自动校准** | `gestic_set_auto_calibration`：18 字节消息（`FE FF` + 16 字节，msg `0xA2`，param `0x0080`，arg0=0，mask=`0x3F`） | 传感器基线漂移 → 坐标整体偏移（正是"画布偏一角"的来源） |
| **P4** | **未设置输出使能掩码** | `gestic_set_output_enable_mask(position|gesture|touch)` | 依赖传感器默认输出集，换固件/上电状态就可能没有位置数据 |
| **P5** | 未发送强制校准 | `gestic_trigger_calibration`（param `0x1000`） | 无法在"手离开时"主动置零 |

### 13.3 建议顺序

1. **P1 + P2**：纯接收侧，改动小，立刻减少假帧（不需要写通路）；
2. **P3/P4/P5**：需要给 reader 加**消息写通路**（§12 已给出寄存器序列），一次做完；
3. 全部完成后再回到 LIVE 出音规则。
