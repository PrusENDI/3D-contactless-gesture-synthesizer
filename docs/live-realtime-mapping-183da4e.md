# LIVE 实时化：以 183da4e 为最终指标的功能对应（2026-10-31 修订）

> **本文取代** `live-realtime-functional-mapping.md`。
> 上一版把 `compile_lead` 的"锚点/段化/merge_leaps"当成实时规则——**错了**。
> 最终设计中 DP 分段只在 **COMMIT** 时跑一次（41 µs），实时链路用的是
> **电平穿越 + 门控切分**。

## 1. 权威依据

| 来源 | 说明 |
| --- | --- |
| `mgc3130_uart` @ **183da4e** `docs/system-design-summary-2026-10-25.md` | **最终设计指标**（用户指定） |
| `tools/synthwave_loop.py` @ HEAD | 规格与回归基准；自 `c6ecaa7` 后未再改动，与 183da4e 一致 |
| `pc_receiver/synthwave_ui.py` | 上位机：只做参数下行与光标显示 |

## 2. 最终硬指标

| 指标 | 值 |
| --- | --- |
| 复音 | **≥4，实现 32 声部**（32×2 振荡器） |
| 端到端延迟 | **≤10 ms（目标 ≤5 ms）** |
| 音频 | **必须 FPGA 逐样本生成**（PC 不产生事件表） |
| 传感 | MGC3130，**200 Hz**，X/Y/Z 16 bit |

## 3. 最终架构（183da4e §12.1）

```text
FPGA：MGC3130 → 锁存 → 光标(alpha/冻结/回滚/限速) → 滤波(中值+IIR)
      → 出音规则(电平穿越 + 门控切分) → 事件表 → 32 声部 → 混音/FX → I2S
PC  ：参数下行(CSR) + 光标遥测显示（不产生事件表）
```

`tools/synthwave_loop.py` 从产品路径**降级为规格与回归基准**：FPGA 输出必须与它逐样本对齐。

## 4. 实时规则（这是上一版最关键的纠正）

| 机制 | 规定 | 出处 |
| --- | --- | --- |
| 出音 | **电平穿越**（pitch 跨过音级边界才换音）+ **门控切分** | §4、§12.1 |
| 门控 | `touch`（接触发声，时值=接触时长）/ `bow`（左右往返各一次） | §4 |
| 同音重复 | 门控切分，落在同一音级 | §4 |
| 大跳 | 跨度 ≥3 音级且快速通过时**不出经过音** | §4 |
| 时间模型 | 绝对时间 → tick；超 128 回绕；**后圈覆盖前圈** | §4 |
| 循环长度 | Auto length：按小节向上取整 | §4 |
| Potts DP | **只在 COMMIT 触发**，41 µs/圈，不进实时预算 | §12.1 |

## 5. 逐环节对照：spec ↔ RTL 现状 ↔ 缺口

| 环节 | spec 要求 | RTL 现状 | 缺口 |
| --- | --- | --- | --- |
| 传感 | 200 Hz | reader 实测约 138 帧/s（触摸时） | 帧率偏低，需确认是传感器配置还是 readout 节奏 |
| 光标 alpha | 1.0 → 0.12（由 Z 控制） | `ALPHA_HIGH_Q16=65536`(1.0)、`ALPHA_LOW_Q16=7864`(0.12) ✅ | 无 |
| 接合/释放 | 30000 / 36000 | `Z_ENGAGE=30000`、`Z_RELEASE=36000` ✅ | 无 |
| 每帧限速 | **≤0.02** | `MAX_STEP_Q16=4096` = **0.0625** | **偏大 3 倍**，需改成 1310 |
| 触控冻结 / 接触前回滚 / 抬手接续 | 要求 | 未实现 | 缺 |
| 音高 | y → G3..C5 → 五声 | `map_note` 已按文档实现 ✅ | 无 |
| **出音规则** | 电平穿越 + 门控切分 | 有 `edge_cross`，但门控切分未实现；当前是"音变即 revoice" | **缺门控切分** |
| 门控源 | touch / bow | 目前 gate = `cursor_engaged`（接近判定） | **缺 bow 往返检测与 touch 接触语义** |
| 大跳抑制 | ≥3 音级快速通过不发音 | 无 | 缺 |
| **tick 时间轴** | 绝对时间 → tick，128 回绕 | `loop_tick = sample_index[6:0]`（≈2.7 ms，**不是音乐 tick**） | **必须新建 BPM→tick**（`BPM=0x08` 也未实现） |
| 循环录制覆盖 | 后圈覆盖前圈 | 录制路径存在，覆盖语义未验证 | 需验证 |
| Potts DP（COMMIT） | 41 µs 一次 | 未实现 | 缺（可砍，§13 排序 4） |
| 声部 | 32×2 振荡器 | 32 声部、双振荡器结构已在 | 需确认逐样本时序预算 |
| FX | 有 | `v2_fx_lite` 存在 | 需确认 50/80 MHz 下的余量 |

## 6. 延迟预算（≤10 ms，目标 ≤5 ms）

| 环节 | 估算 | 说明 |
| --- | --- | --- |
| 传感器帧间隔 | **5 ms**（200 Hz） | 已是硬下限；实测 7.2 ms（138 Hz） |
| 光标滤波 | 1 帧 | 中值窗 + IIR |
| 出音规则 | 1 帧 | 电平穿越/门控切分 |
| 事件 → 声部 | <0.1 ms | 事件握手 |
| 声部扫描 | 32 声部 ≤ 1 ms（80 MHz） | 需实测 |
| I2S 缓冲 | 1 样本 @48 kHz = 20.8 µs | — |
| **合计（理想）** | **≈ 12 ms（200 Hz）/ 14 ms（138 Hz）** | **已超 10 ms** |

**结论：要在 ≤10 ms 内，必须把传感帧率提到 200 Hz（5 ms/帧），并让"光标+出音"只占 1 帧。**
当前 138 Hz 的 readout 节奏是两个帧间隔（14 ms），先把这一点查清，比改算法收益大。

## 7. 与上一版设计的差异（记录，避免再走错）

| 上一版（错误） | 最终设计 |
| --- | --- |
| 实时跑 anchor/segment/merge_leaps | 实时只做**电平穿越 + 门控切分** |
| 实时插入 rest、按段长决定时值 | 时值由**门控时长**（touch）或**往返半程**（bow）决定 |
| merge_leaps dwell=2 | 大跳由"跨度≥3 且快速通过"抑制，无需前瞻 |
| 段化后才量化 | 每帧量化 + 穿越判决 |

## 8. 下一步（按 183da4e §13 的顺序）

1. **确认传感帧率**：为什么是 138 Hz 而不是 200 Hz（readout 命令 / TS 节奏 / 配置）；
2. **tick 时间轴**：实现 `BPM → 16 分音符 tick`、128 回绕；
3. **出音规则**：电平穿越 + 门控切分（touch/bow），大跳抑制；
4. 光标限速改 0.02、补触控冻结/回滚/抬手接续；
5. 逐项与 `synthwave_loop.py` 对齐做回归。

## 9. 需要你确认

1. 传感帧率 138 Hz 是**实测的传感器上限**，还是我们 readout 的节奏问题？
2. 门控默认用 `touch` 还是 `bow`？（spec 两者都要，实时只能选一个作为 LIVE 默认）
3. 大跳抑制的"快速通过"阈值：用 tick 数还是帧数？
