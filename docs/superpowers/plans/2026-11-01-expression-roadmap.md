## 1. 目标

把现在"能跑但单薄"的乐器，补到**赛题拓展要求**与**评分规则**的口径，并且每一步都能拿出证据。

赛题原文（用户提供，2026-11-01）：

| # | 要求 | 原文要点 |
| --- | --- | --- |
| R1 | 超大规模并行合成引擎 | 复音 ≥32，或加法分量 ≥32 路，或多条并行物理建模单元 |
| R2 | 多维表情 + 音频效果 | **≥3 维**表情（力度动态、滑音、颤音…）；**≥2 种音色自由切换**；FPGA 内实现**混响、延迟、合唱** |
| R3 | 极致低延迟 + 视听反馈 | 演奏延迟 **≤5 ms** 且确定无抖动；硬件实时生成可视化（LED 指引、李萨如、实时频谱、波形） |
| R4 | 智能联动/脱机 | 脱机 LED 曲目指引；蓝牙 + 手机 App（在线曲谱/键位自定义/录音回传） |
| S1 | 振荡器统计口径 | 一路 = **独立相位累加器 + 频率调控 + 包络控制**；单波表查表不计谐波，只算 1 路 |
| S2 | 吞吐量 | **活跃独立振荡器数 × 实际输出采样率**，过采样不加分 |
| S3 | 现场验证 | 测试模式输出**多路不同频率**、频谱见**对应数量独立谱峰**；RTL 可佐证纯硬件合成、无预录音频 |

用户已定的口径（2026-11-01）：

- **延迟不含 MGC3130 传感器**：量的是事件→DAC，传感器 138 Hz 帧率不计入；
- **测试模式做成独立位流**，生产位流不带（已完成参数化）；
- **滤波器**：整台琴**一个全局滤波器**，由**一个 LFO 扫截止频率**；
- patch bank 不砍，但要知道它只是"参数名"，需要瘦身 + 接线（见 §3）。

## 3. 组件缺口与赛题映射

| 缺口 | 对应赛题 | 必要程度 | 成本估算 |
| --- | --- | --- | --- |
| **VCA：包络真的乘到样本** | R2 力度动态 / S1 包络控制 | 必做（"单薄"首因） | 1 DSP + ~100 LUT |
| **全局二阶滤波器（含共振）** | R2 音色 | 必做（用户已定） | 2–3 DSP + ~400 LUT |
| **LFO（正弦/三角，速率+深度）** | R2 / 用户已定扫截止 | 必做 | ~100 LUT |
| **滤波包络（ADSR→截止）** | R2 表情（标准减法合成器的"哇"） | 强烈建议 | 复用包络 + 加法器，~150 LUT |
| **滑音可控（GLIDE_MS）** | R2 三维表情 | 必做 | ~50 LUT |
| **颤音（LFO→vibrato）** | R2 三维表情 | 必做 | ~0（端口已在） |
| **振荡器失谐（±cents）** | R1/S1 的 64 路主张 | 必做（否则只能算 32） | ≈0（写不同 step） |
| **每振荡器包络** | S1 口径 | 建议（拿 64 路） | 1 BSRAM + ~150 LUT |
| **混响 + 合唱** | R2 效果器 | 必做（赛题点名） | 2 BSRAM + ~600 LUT + 1–2 DSP |
| **主音量/限幅** | R3 听感、防削顶 | 建议 | ~200 LUT |
| **LIVE 并入 32 声部引擎** | 现场"活跃振荡器数"口径 | 建议 | 净 ≈0（删单声部出口 ~300 LUT） |
| **独立测试位流（多路不同频率）** | S3 现场验证 | 必做 | 独立位流，不占生产 |
| **可视化（LED/李萨如/频谱/波形）** | R3 | 待定（硬件待确认） | 未知，需先确认板上有无 LED/显示 |
| **脱机 LED 指引 / 蓝牙 App** | R4 | 待定 | 大，需单独评估 |

预算现状（CLS 是硬约束）：**空闲 1022 CLS ≈ 1600 LUT 当量**。瘦身 patch bank 可回收 ~660 LUT，
LIVE 合并可回收 ~300 LUT → 总可用约 **2500 LUT 当量**，上面"必做"合计约 1500 LUT + 4–5 DSP（DSP 有 22 个空闲）。

## 4. 三条路线

| 路线 | 内容 | 优点 | 代价 |
| --- | --- | --- | --- |
| **A. 最小可听闭环** | VCA → 全局滤波 + LFO → 独立测试位流 | 两三步内解决"单薄"，每步都能上板听 | 离 R2 的"三维表情/效果器"还差；64 路主张不成立 |
| **B. 赛题覆盖（推荐）** | A 的全部 + 滑音/颤音/滤波包络 → 失谐 + 每振荡器包络（64 路）→ 混响/合唱 → LIVE 合并 → 可视化 | 逐条对上 R1/R2/S1/S2/S3 | 阶段多，需要 6–8 轮；CLS 会顶到 ~100% |
| **C. 先稳后加** | 先修 R13/R14、时序（UART 锥）、CLS 余量，再加功能 | 工程最干净 | 比赛进度慢，且"单薄"问题继续存在 |

**推荐 B，但按 A 的顺序落地**：每个阶段独立可验收、可回滚；P1+P2 就能上板听到明显改善，
后面的阶段即便来不及也不影响已有成果。

## 5. 分阶段计划

每个阶段的统一门槛（缺一不算完成）：

1. `python scripts/gate.py --compile` → 0 error / 0 warning；
2. `python scripts/sim.py` → PASS 且失败集不超出基线；
3. 该阶段新增/修改的单元 tb 绿（先红后绿，红证要留下）；
4. `python scripts/synth.py --run-id <id>` → SYNTH PASS，记录 LUT/Reg/CLS/DSP/BSRAM + 时序四件；
5. 板级验收脚本 + 读数（或明确写明"本阶段无板级判据"）；
6. `docs/progress-2026-11-01.md` 记证据，`git add <具体文件>` 提交。

### P0 收尾：参数面瘦身与占位（0.5 轮）

- patch bank：从 4 族 × 8 轨 × 32 项缩到**一套全局参数**（~16 项：OSC_MIX/BRIGHTNESS/DETUNE/ADSR/GLIDE/VIBRATO_HZ/VIBRATO_CENTS/GAIN/FILTER_CUTOFF/RESONANCE/FILTER_ENV/LFO_RATE/LFO_DEPTH/LFO_WAVE），保留 shadow/active + CRC/APPLY 语义与 `0x48–0x5C` 地址；
- 释放 ~660 LUT、~200 寄存器；
- 验收：`gate`/`sim.py` 不回归；`0x48–0x5C` 的读写/APPLY 有 tb（当前没有）。

### P1 表情基础：VCA + 滑音 + 颤音（1.5 轮）

- VCA：`calc_osc_sum` 乘上 `calc_envelope`（1 DSP），释放段才有真正的尾音；
- 滑音：`bounded_step` 的 512 步长由 `GLIDE_MS` 参数换算；
- 颤音：`vibrato_hz/cents` 由 LFO 驱动（LFO 在 P2 完整实现，这里先用参数直连）；
- 验收：新 tb 断言"包络乘到输出"（固定样本 × 包络阶梯 = 期望阶梯）、滑音时长、颤音频偏；板上听感：起音/尾音/滑音/颤音可辨。

### P2 全局滤波器 + LFO 扫截止（2 轮）

- 二阶低通（状态变量或 direct-form I），12 dB/oct，Q 可调；
- 位置：**最终 I2S mux 之前**（LIVE/WT_PLAY/PLAY 都过它），旁路开关；
- LFO：正弦/三角可选、速率 0.05–20 Hz（或 tempo 同步）、深度 0..1；
- 可选：滤波包络（ADSR→截止）与 LFO 相加；
- 验收：tb 断言截止频率响应（扫频/冲激）、LFO 周期；板上：GAO 抓 `i2s_sample` 观察 LFO 周期与频谱重心移动。

### P3 64 路主张：失谐 + 每振荡器包络（1.5 轮）

- 每声部写不同 `step_a/step_b`（±cents），初始相位错开；
- bank 记录加第二个包络（256 → 272 bit，多一条 DPB lane）；
- 验收：tb 断言两路频率不同、两个包络独立；按 S1 口径写出"64 路完整振荡器"的对照表（相位累加器/频率/包络逐项对应 RTL）。

### P4 LIVE 并入 32 声部引擎（2 轮）

- LIVE 改由声部引擎出音，`wt_source_sel` 按模式区分（测试位流仍可用锯齿）；
- 删除单声部出口（`v2_wt_playback`/顶层 `u_wt_mix`/门控包络/`wt_quiet`），WT_PLAY 改走引擎或明确废弃；
- 验收：同一帧同一 position 下 LIVE 与 PLAY 的 GAO 频谱差 ≤3 dB（计划里一直没做的判据）；电平用 shift/trim 对齐。

### P5 效果器与输出级（2 轮）

- 混响（2–4 条 comb + 1–2 allpass，BSRAM 有余量）、合唱（短延迟 + LFO 调制）；
- 补 delay 参数化；主音量 + 软限幅；
- 验收：tb 断言混响尾音长度/合唱调制深度；板上 GAO 观察。

### P6 独立测试位流（1 轮，可与 P5 并行）

- `USE_TEST_MODE=1` 的独立位流；把测试模式升级成 **N 路不同频率**（N=1/8/32/64），覆盖 S3；
- 验收：板上烧测试位流，频谱仪/GAO 数出 N 个独立谱峰；记录 sha256（与生产位流分开记）。

### P7 可视化（待定，先确认硬件）

- 先确认板上有无 LED/显示资源（当前仓库没有任何 LED 驱动）；
- 可视化数据从哪来（遥测 20 Hz 不够"实时频谱"，可考虑板上 FFT 或直接波形/李萨如）；
- 这一步的规模取决于硬件，先做一次只读勘察再定计划。

### P8 赛题材料（0.5 轮，收尾）

- 吞吐量计算表（活跃振荡器 × 48 kHz，32/64 两档）；
- RTL 佐证清单（相位累加器、频率、包络、滤波器、效果器逐项对应文件与行号）；
- 现场演示脚本（上传音色 → PLAY/LIVE → 切音色 → 滤波扫频 → 测试位流数谱峰）。

## 6. 非目标（本轮明确不做）

- MGC3130 传感器链路的延迟优化（用户已定延迟不含传感器）；
- 每声部独立滤波器（32 份乘法器，面积不允许）；
- 物理建模引擎、FM/加法合成引擎（赛题给了多选，我们走波表复音）；
- 蓝牙 + 手机 App（R4 的可选项，需要外部硬件与 App，单独立项）。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| CLS 已 91%，P1–P5 合计约 1500 LUT | 顶到 100% 后 P&R 失败 | 每阶段结束记录 CLS；P0 先回收 660 LUT；超过 97% 就暂停加功能，先做面积回收 |
