# 上位机控制台 v2 实施计划（音色编辑器 + 演奏视图）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `host/v2_console/` 建一个零新依赖的桌面控制台：一个串口线程、九个参数寄存器、可存盘的预设、三块实时画布，能把听到的声音存下来并一模一样地放回去。

**Architecture:** 传输层（`link.py`）做流水线发送与帧解析，会话层（`session/`）做所有权、工作流与证据日志，参数层（`params.py`）把九个寄存器翻成带单位的控件，预设层（`presets.py`）存寄存器原值，画布层（`canvas/` + `views/*_painter.py`）按显示列表绘制、不碰 tkinter，外壳（`views/shell.py`）只做装配。

**Tech Stack:** Python 3.10.11、pyserial 3.5（唯一外部依赖）、tkinter 8.6、标准库 `unittest`/`wave`/`winsound`。**不用 pytest、不用 numpy。**

**Spec:**
- 父设计：`docs/superpowers/specs/2026-11-02-console-design.md`（传输、参数、预设、外壳、证据）
- LOOP 专篇：`docs/superpowers/specs/2026-11-02-loop-canvas-assisted-recording-design.md`（画布坐标、录制状态机、参考音轨）

执行者两份都读。冲突时：画布与录制归专篇，其余归父设计。

## Global Constraints

- Python 3.10.11；依赖只有 `pyserial`；测试用 `python -m unittest`（仓库既有约定）。
- 源文件 **LF、无 BOM**；`gate.py` 对 BOM 报错。
- 串口 **一个拥有者**；默认 `COM4`、1 Mbaud；单条命令超时 **400 ms**；重发**同 seq 同字节**一次，再失败即中止整个工作流。
- 流水线节拍 **默认 320 µs**；有实测依据前，1024 点上传按逐条等 ACK（≈18.3 s），验证通过才允许突发。
- **绝不写** `0x10`（PLAY，未实现）、`0x2C`（RESET，空操作）、`0x48–0x5C`（已删除的 patch 区）。
- 每次写寄存器都**读回**；读回 ≠ 写入（clamp）时显示"已 clamp"，读回 ≠ 预设值时算失败。
- 预设文件里只存 **0..2³²−1 的整数寄存器原值**，不存浮点、不存滑杆位置。
- 不改 RTL。CLS 10750/11520、DSP 28/28 与本计划无关。
- 每个任务用 `git add <具体文件>` 提交，提交信息写"改了什么 + 为什么"。

## Review Focus

按"最可能咬到使用者"排序，每一条都由下面点名的任务用测试钉住：

1. **串口中途被拔掉**：每条命令必须 400 ms 内抛 `LinkLost`，界面回到"未连接"，不能卡死或静默丢命令（Task 3）。
2. **迟到的上一条回复**（seq 不匹配、CRC 也合法）：必须丢弃并重试，不能当成本条成功（Task 3）。
3. **板上还开着遥测**（`board_cursor.ps1` 遗留）：ACK 与 20 Hz 遥测帧混在一条流里，解析器必须按 `[2]` 分流且不吞 ACK（Task 2、Task 6）。
4. **手改过的预设带掩码外的位**（如 `0x9C` 写 `0x0000FFFF`）：板子回 `BAD_DATA(0x07)`，界面要指出是哪一条，其余九条不写（Task 8）。
5. **手不在感应区**：遥测完全静默，界面不能报"串口无数据"，要显示"等待光标"（Task 10、Task 15）。

- [ ] **Step 3: 实现**

- `command`：seq 递增（模 256），发包前 `reset_input()`？**不**——重发要靠重复帧缓存，先清空会破坏恰好一次。改为：记录本命令的 seq，解析到的回复若 seq 不匹配则丢弃并继续等（超时预算不变）。
