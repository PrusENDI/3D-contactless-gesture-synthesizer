# 整机低通滤波器 + LFO 扫截止：设计（2026-11-01，评审后修订 r2）

> 目标版本：`mgc3130_clean` HEAD 之后（P1 已完成）。本文件是 P2 的设计，批准后才写任务级计划。
> **r2 修订原因**：独立评审指出 r1 的共振阈值算法错了（用连续时间模型、忽略了反馈的一拍延迟），
> 我独立复核后确认。§5.2/§5.3/§6 因此重写，控制面与 LFO 不变。逐条答复见 §10。

## 1. 意图与为什么

现在的音色薄，根因不是振荡器不够，而是**没有任何频谱塑形**：32 个声部把满幅波表直接送进 I2S，
高次谐波全在，听感"亮而空"。标准合成器的听感一半来自滤波器——尤其是**带共振的低通**与
**缓慢扫动的截止频率**（LFO → cutoff）。赛题的"表情"项也希望整机有可听、可演示的连续变化。

所以 P2 只做两件事：一个**整机共用的 4 极点低通**（24 dB/oct，带共振），一个**三角 LFO**
把截止频率在对数域上缓慢扫动。上电默认**旁路**，行为与今天完全一致；主机显式打开后才改变音色，
因此既往验收过的电平/频谱证据不会失效。

## 2. 目标

1. 三条音频出口（`PLAY` 的 32 声部、`LIVE` 单声部、`WT_PLAY` 台架）都经过同一个滤波器；
2. 截止频率、共振、LFO 波形/速率/深度/重触发可经 CSR 控制，且**可读回**；
3. **参数面**（§11）：把 `v2_fx_lite` 里已有但被写死的六个参数接到 CSR（0 DSP，补赛题 R2 的
   硬件延迟/混响），加一个主音量，再把 32 声部引擎的四段包络/力度深度/失谐倍率/滑音速率
   从编译期常数变成寄存器——**这些都不需要实时**，写一次即可；
3. 旁路时**比特级透明**（输出直通，滤波器照常运行，只是不选它）；
4. 任何 (截止 × 共振 × LFO) 组合都不发散，输出恒在 int16 内；
5. 面积 ≤ 450 LUT、≤ 6 DSP、1 BSRAM（预算：CLS 剩 1010、DSP 剩 20、BSRAM 剩 19）。

## 3. 非目标 / 反目标

- 不做滤波包络（ADSR→截止）、不做键盘跟踪、不做高通/带通/陷波；
- 不做每声部独立滤波（整机一个，用户已定）；
- 不做 LFO 波形选择（只有三角）、不做 BPM 同步；
- **不做自激**（理由见 §5.2，一行常数即可改成允许）；
- **不改 `v2_fx_lite` 的 DSP**，只把它的参数接到 CSR（§11.2）；
- **反目标**：为了让规格好看而把"截止 18 kHz"当成 −3 dB 点——两者差一个常数，§5.4 写清楚。

## 4. 约束（来自现有代码，不是猜的）

| 约束 | 值 | 出处 |
| --- | --- | --- |
| 采样率 / 时钟 | 48 kHz / 80 MHz → **每个采样 1667 个时钟** | `i2s_pcm5102a_tx` `CLK_HZ(80e6) SAMPLE_HZ(48e3)` |
| 插入点 | `i2s_sample` 的 4 路 mux 之后（三条出口都经过） | `mgc3130_v2_top.sv:658` |
| **滤波器的时基** | **`sample_ce`**（连续 48 kHz 节拍），**不是** mux 后的 `i2s_sample_valid` | 见 §5.6 与 §10 Q2 |
| 延迟 | 1 个采样（20.8 µs），不延迟 I2S 的 valid | 同上 |
| 面积余量 | CLS 10510/11520、DSP 8/28、BSRAM 37/56 | `impl/v2_board_top_vca_detune_mbox` |
| 时序余量 | worst −3.214 ns（在 UART，不在音频路径） | 同上 `.tr` |

**关键推论**：1667 个时钟/采样意味着滤波器可以多周期流水；**DSP 富余、LUT 紧张**，所以用
并行乘法器（每级一个）而不是时分复用，用 1 块 BSRAM 存系数表。

## 5. 方案

### 5.1 三个候选与取舍（用户选了 B）

| | 结构 | 音色 | 代价 |
| --- | --- | --- | --- |
| A | 状态变量 12 dB/oct | 干净、Q 可到 8 | tan 查表；−3 dB 上限更高 |
| **B ✅** | **梯形 4 极点 24 dB/oct，ZDF 解反馈** | **像合成器：厚、共振峰均匀、可自激** | 1 BSRAM（G 表 + 倒数表）+ 4~6 DSP；8 个状态 |
| C | 两级一极点级联 12 dB/oct，无共振 | 只压高频 | 最便宜，放弃共振 |

选 B 的理由：用户诉求是"音色单薄"，24 dB + 共振最能改观；系数在对数域（1/48 八度一档），
LFO 直接加在对数域上就是音乐化扫频。代价是 r1 低估的那一点（1 块 BSRAM + 倒数表），
在 19 块空闲 BSRAM 里可以接受。

### 5.2 结构（r2 重写）

每级用**双线性（TPT）一极点**，全环做**零延迟反馈（ZDF）**解算：

```
            ┌──────────────────────────────────────────┐
x ──►(+)──► u ──► [P1] ──► [P2] ──► [P3] ──► [P4] ──► y4 ──► 饱和 ──► out
      ▲-                                                    │
      └──── K·S ◄──── ZDF 解 ───────────────────────────────┘

每级： v_i = G·(u_i − s_i)， y_i = v_i + s_i， s_i ← y_i + v_i
四极点： y4 = G⁴·u + S，  S = (1−G)·(G³s₁ + G²s₂ + G·s₃ + s₄)
反馈解： u = (x − K·S) / (1 + K·G⁴)
```

**为什么必须 ZDF（这是 r1 的错误）**：若像 r1 那样把反馈取上一拍的 `y4`（一拍延迟），
振荡阈值 `Kcrit` 与截止频率强相关且**非单调**（实测：ci=0 时 1.00、ci=8 时 3.61、
ci=16 时 11.18、ci=32 时 9.00、ci=96 时 4.6）。后果是：ci ≤ 8（"全开"那一端）K=3.9
已经超过阈值 → 变成 24 kHz 满幅方波；而 ci=32 附近 K ≤ 3.9 又完全激不起共振。

ZDF 解算后（实测，见 §5.3 表）：**|P| = 0.2500、∠P = ±180° 恰好落在设计 fc 上，与截止无关**，
于是 **Kcrit = 4.000 对所有截止成立**，K=3.75 的峰值 **+14.0…+15.2 dB**（从 40 Hz 到 18 kHz
只差 1.2 dB）。这就是要的"旋钮含义一致"。

- `K = res·3.75/256`（res 0..255），**上限 3.75 < 4**：不做自激。想允许自激只需把上限改成 4.02，
  但那时输出幅度由饱和器决定、会盖掉别的声部，本轮不做；
- 输出整型饱和（共振峰值 +15 dB 会削顶，这是刻意的、可听的控制）；
- 反馈项 `K·S` 用宽位宽算，不先饱和（先饱和会改变谐振频率）。

### 5.3 系数与截止映射（r2 重写，全部实测）

`ci` 是截止索引，**1/48 八度一档**，`fc(ci) = 40 Hz · 2^(ci/48)`（一极点的设计频率）；
`G = q/(1+q)`，`q = tan(π·fc/fs)`；`ci` 夹到 `[0, 423]`（fc ≤ 18 kHz）。

| ci | fc（一极点） | G | 4 极点 −3 dB | K=3.75 峰值 |
| --- | --- | --- | --- | --- |
| 0 | 40.0 Hz | 0.00261 | 18.0 Hz | +14.0 dB |
| 96 | 160 Hz | 0.01036 | 70 Hz | +15.0 dB |
| 144 | 320 Hz | 0.02052 | 139 Hz | +15.2 dB |
| 192 | 640 Hz | 0.04023 | 278 Hz | +15.2 dB |
| 240 | 1.28 kHz | 0.07747 | 557 Hz | +15.2 dB |
| 288 | 2.56 kHz | 0.14467 | 1.12 kHz | +15.2 dB |
| 336 | 5.12 kHz | 0.25829 | 2.29 kHz | +15.2 dB |
| 384 | 10.2 kHz | 0.44215 | 5.06 kHz | +15.2 dB |
| 423 | 18.0 kHz | 0.70649 | 12.3 kHz | +15.2 dB |

一张 **1024×18 的 BSRAM** 装三张表：`G[0..511]`（ci > 423 的项填 fc=18 kHz 的值）、
`R[512..767]` = `1/(1+x)`、`SIN[768..1023]`（LFO 正弦，见 §11.2）。
`x = K·G⁴`，而 `G⁴ ≤ 0.706⁴ = 0.249`、`K ≤ 3.75` → **x ∈ [0, 0.93]**（判评审指出的笔误：
不是 3.5）。所以 R 表只需覆盖 [0, 0.94]，256 项的分辨率 0.37%，ZDF 修正项误差 <0.1 dB。
G⁴ 用两次乘法现算（G²=G·G，G⁴=G²·G²），省掉第三张系数表。

### 5.4 截止上限的诚实说法（r2 修正）

一极点的设计频率可以到 18 kHz（G=0.706），但**4 极点级联的 −3 dB 只有它的一极点 fc 的约
0.43 倍**（越靠近 Nyquist 这个比例越大：5 kHz 时 0.45、15 kHz 时 0.59）。所以：

- 规格写成 **"一极点 fc 40 Hz…18 kHz；4 极点 −3 dB 18 Hz…12.3 kHz"**，两个数都给出；
- 12.3 kHz 以上没有"更开"可言——再往上就是**旁路**，不是靠推截止；
- 路线图里的"20 Hz…18 kHz"是愿望值，本设计把上面两行写进 GUI 文档，避免以后拿它去对表。

### 5.5 LFO（已定）

- 32 位相位累加：`inc = (rate_mHz · 45813) >> 9`（Q9 的 2³²/48000/1000 = 89.478，误差 <0.1%）；
- 三角：`tri = phase[31] ? ~phase[30:0] : phase[30:0]`，双极 `b = tri − 2³⁰`（±2³⁰）；
- 调制加在**对数域**：`off = (b · depth) >> 30`（depth 0..255 → ±depth 个 ci 单位；
  1/48 八度 → 最大 ±5.3 八度）；`ci_total = clamp(ci + off, 0, 423)`；
- depth=0 时截止完全不动；LFO 不改变共振与输出电平；旁路时相位**继续推进**。

### 5.6 时基与旁路（r2 新增，评审 Q2 的答复）

- 滤波器用 **`sample_ce`** 使能，而不是 mux 后的 `i2s_sample_valid`。理由：`i2s_sample_valid`
  在 LIVE 里是 `(mode_live && live_gate) && sample_ce`——手势门关掉时**一个脉冲都没有**，
  滤波器状态与 LFO 相位都会被冻住（LFO 速率就不再是 48 kHz 恒定）；而源端其实每个
  `sample_ce` 都在产生样本。
- 输出寄存器在下一个 `sample_ce` 之前就已稳定，所以**不需要**给 I2S 的 valid 加延迟，
  代价是 **1 个采样（20.8 µs）的延迟**。总延迟预算（事件→DAC ≤5 ms）里可以忽略。
- 旁路 = **输出二选一**，滤波器照常运行（状态跟着信号），因此开关瞬间没有阶跃；
  旁路时 I2S 拿到的是未滤波的 `i2s_sample`，与今天逐位相同。

### 5.8 与现有波表 LFO 的关系（用户已定：各自独立）

板上已经有一个慢速 LFO：`v2_wt_position` 是 Q2.24 的三角位置，`0x60 WT_SELECT[8]` 使能、
`[31:9]` 每采样步进（20 s 单程 = 35），输出 `frame_a / frame_b / frac` 做**帧间 morph**
（WT_PLAY/LIVE 的单声部与 PLAY 的 32 声部都受 `wt_morph_en` 管）。

两者**不冲突**，因为地址、单位、数据通路、资源都分开；但有三处刻意不同，GUI 必须分清：

| 维度 | 波表 morph LFO（现有） | 滤波 LFO（本设计） |
| --- | --- | --- |
| 配置 | `0x60[8]` 使能、`[31:9]` 步进/采样 | `0x44`：mHz 速率 + ci 深度 + 使能 |
| 触发 | `morph_en` 上升沿归零（它是个位置） | 一直按 `sample_ce` 推进，旁路也不停 |
| 作用 | 表读地址的帧插值 | 截止索引 ci |

**决定：两个独立相位累加器，不共用。** 共用可省约 30 个触发器，但两个扫动从此锁相，
失去交叉动感（例如 morph 往暗帧走、截止同时往开走）。资源代价可以忽略。
BSRAM 也不重叠：滤波系数表 1 块，波表仍占原有 6 个 bank（38/56）。

## 6. 验收判据（r2 重写）

**单元（先红后绿，红证留在日志里）**

1. `tb_filter_ladder`（用 `host/filter_reference.py` 的浮点模型做黄金参考）：
   - 旁路 = 比特级直通；
   - **延迟 1 个采样**：同一个冲激，输出比输入晚一拍（不是两拍、不是零拍）；
   - K=0 时 4 极点级联的 −3 dB 与 §5.3 表对比：ci = 96 / 192 / 288 三点，容差 ±15%；
   - **共振单调**：ci=192，res = 0 / 85 / 170 / 255 的峰值单调上升，res=255 时 +15 dB ±2 dB；
   - **共振均匀性（评审要求的断言）**：res=255 在 ci = 48 / 192 / 336 三处的峰值差 ≤ 3 dB；
   - **不发散**：全量程扫描（ci 0..423 × res {0,128,255} × LFO 深度 {0,255}）每点 2000 采样，
     输出恒在 int16 内，且任何一点的最大值不得超过 32767（这是"不发散"的唯一判据）；
   - 饱和不回绕：给一个 4 倍满幅的正弦，输出是平顶而在 0 附近不出现反相尖峰。
2. `tb_lfo_triangle`：速率字 → 周期（±2%）；depth=0 时 ci 恒定；depth=255 时偏移峰峰 =
   2×255 ci 单位；ci 夹在 [0,423]；旁路时相位继续推进。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 高 K 固定点发散 | ZDF 保证 Kcrit=4 与截止无关，K 上限 3.75；再加输出饱和作为兜底；§6 全量程扫描 |
| ZDF 解算的倒数表误差 | 256 项覆盖 x∈[0,0.94]（0.37%），修正项误差 <0.1 dB，tb 容差按此设 |
| 旁路↔开启切换爆音 | 滤波器在旁路时照常运行，只切输出（§5.6） |
| 共振让整体电平变高、削顶 | 输出饱和；若实测整体过响，加一个常数衰减（不引入 CSR） |
| CLS 上涨 | §11 之后总预算约 450~600 LUT、DSP 约 6~8 个：**撞 11000 CLS 就先只做 P2a、P2b 延后**，不动 patch bank（用户决定留着） |
| 时序 | 1667 时钟/采样；worst slack 是**门**（§6），不合格先加流水 |

### 11.2 P2a 的语义（要说清的七点）

1. **效果器只作用于 PLAY**：`v2_fx_lite` 挂在 `fx_quiet` 那一支，LIVE 与 WT_PLAY 不经过它。
   文档与 GUI 必须写"延迟/混响只影响 PLAY"，否则用户会以为 LIVE 也该有。
   `fx_cutoff_q16` 是 `v2_fx_lite` 内部那个一极点的系数（不是我们的梯形滤波器）。
2. **`gain_q16` 与 `cutoff_q16` 不受 enable 管**（读代码：`level_now = fx_enable ? fx_level : 0`，
   但 `gain_value = in·gain>>16` 与 `lp_value` 一直算）。所以**复位值取今天的编译配置**
   （`enable=FX_ENABLE`、`level=FX_LEVEL`、增益 1.0、截止 0xFFFF），而不是"全 0"：
   照"全 0"写 PLAY 会立刻变哑。板上 `v2_board_top` 编译的是 `FX_ENABLE(1) FX_LEVEL(1)`，
   复位 `0x0015_0000`；tb 里 `FX_ENABLE(0)`，复位 `0x0001_0000`。这两个参数从此只当复位值用。
3. **`fx_level` 不是混合量，是 4 档链条选择**：0=干、1=加低通、2=再叠延迟、3=再叠梳状（混响感）。
   GUI 要用"效应档位"，不能做成 wet 旋钮，否则用户会以为能连续调。
4. **`feedback_q15 ≥ 1.0` 会自激跑飞**：契约的 `op_data_ok` 必须把上界夹到 **0.9（`0x7333`）**
   （`reverb_mix_q15` 夹 1.0），否则一条 0xFFFF 就能让板上留下一个越来越响的回声。
5. **主音量在滤波之后、I2S 之前**，三路都经过；默认 `0x10000`=1.0 时**逐位不变**（回归必须证明）。
   上限 2.0 后接一个饱和器（约 30 LUT），不允许回绕。
6. **LFO 扩展**：`waveform` 0=三角 1=正弦 2=锯齿 3=方波 4=随机 S&H；正弦表 256 项塞进**同一块
   BSRAM**（G[0..511] + R[512..767] + SIN[768..1023]，正好 1024 项，所以 R 表从 384 项缩到 256 项）；
   `x = K·G⁴ ≤ 3.75 × 0.706⁴ = 0.93`，R 表只覆盖 x∈[0,0.94]，256 项的分辨率 0.37%（见 §5.3）；
   `retrig`=1 时在 note-on 事件或进入 PLAY 时把相位归零；
   `unipolar`=1 时只在设定截止之上单方向调制（经典滤波包络感），`ci` 是"静止点"。
7. **FX 的三个量必须由契约夹住**（不是靠 DSP）：延迟写是**截断**不是饱和、梳状环是单位增益，
   所以 `feedback_q15 ≥ 1.0` 或 `gain_q16 > 1.0` 会回绕并留在显存里。夹的上界见 §11.6。

### 11.3 P2b 的语义（与既有模块的接口）

包络四段/力度深度/失谐倍率/滑音速率打包成**一条 `voice_cfg` 总线**进 `v2_voice_engine_banked`：

- 现在这些是模块内 `localparam`（`ATTACK_STEP 4096` 等），改成输入会让 7 个既有 tb 都要改端口。
  用**一条打包总线**（`input logic [127:0] voice_cfg`）+ 契约包里的 `V2_VOICE_CFG_DEFAULT`
  作为默认值 → 每个 tb 只加一行 `.voice_cfg(V2_VOICE_CFG_DEFAULT)`，且默认值只有一个来源；
- **力度深度与失谐宽度都在激活时算，但一个用乘法、一个只用移位**（事件路径，不进热路径）：
  - `stored_gain = 255 − ((255 − velocity)·velocity_depth >> 8)`，depth=255 时 **等于原值**（逐位保持
    P1 的基线），depth=0 时所有音符都是 255（力度不起作用）。**注意**：不能写成 `velocity·depth>>8`，
    那样 depth=0 就是静音，而不是"力度失效"。
    这条公式还顺带把 `attenuate_sample()` 里那 0~3 bit 的力度衰减一起解决了——因为它读的就是
    存进 bank 的 `gain` 字段，depth=0 时它看到 255，就不再按力度分档衰减；
  - 失谐宽度用 **`detune_shift`（2 位，加到已有的移位上）**，不是倍率乘法：
    `shift = 11 − velocity[7:6] + detune_shift`（夹到 ≤15），`det = base >> shift`。
    default 0 = P1 行为；每加 1 就窄一半（最多窄 8 倍）。**纯接线、0 DSP**，且激活写回那条锥
    （寄存器→乘法→BSRAM 写数据，P1 前的 21.3 ns 那条）**长度不变**——这是评审 Q4 的答案；
  - `velocity_depth` 的 8×8 乘法在**接受事件那一拍**算，操作数直接来自 `event_data`（不经过音符
    ROM），所以是新起的一条短锥（约 5.3 ns + 1 ns），不叠加在那条 ROM→写数据的锥上；
- `glide_rate` 替换 `bounded_step` 里写死的 `512`（calc 级，寄存器输入，无新增运算）；
- **只影响 32 声部引擎（PLAY）**：LIVE 的单声部路径没有包络，改了也听不到 → GUI 要注明；
- **不解** REVOICE 抹平失谐的老问题（那要把失谐挪进 calc 级），仍列为已知限制；
- `mix 默认值` 这一轮不做：`0x9C` 已满，而它只影响 LIVE 单声部的默认混合，下一轮换地址再说。

### 11.5 验收（在 §6 之上追加）

- P2a：`0x90` 复位值（1.0）时回归必须逐位不变；`0x84` 写 **`0x0015_0000 | 档位`** 后 PLAY 有延迟/混响
  回声（板上听；只写 bit20 而增益不是 1.0 就是静音，所以板上向量写全字，见 §11.6）；
  `0x44[25]` 重触发时相位归零（tb 断言跨 note-on 的相位）；`0x44[29:27]` 五种波形各自可辨
  （tb 断言形状特征：三角的线性段、方波的两电平、S&H 的分段常数）；
- P2b：`0x94/0x98` 写小值 → 起音变短（tb 测起音到顶的采样数）；
  **`0x9C[7:0]=0` → 两种力度的峰值相等且都等于 depth=255 时高力度那个值**
  （必须同时断言"不为 0"，否则"静音也相等"会让断言假绿——评审 Q1 的教训）；
  `0x9C[9:8]` 每加 1，同一力度下的失谐量减半（tb 直接量 bank 字里的 `step_a − step_b`）；
  `glide_rate` 越大滑音越快（tb 断言到达目标所需采样数）；
- 每段各自的构建与门禁按 §6，两段分开记录四个时序数与 sha256。

### 11.6 契约校验：clamp 还是 NACK（评审 Q2/Q5 的答复）

**决定：clamp（写入成功、值被夹住、读回就是夹后的值），不是 NACK。** 理由：参数写被 NACK 时
主机很容易忽略掉，然后在板上留一个"我没写成功但我以为写成功了"的状态；clamp 至少保证器件安全。

`v2_contract_pkg.sv` 里新增一张 clamp 表（`op_data_ok()` 里按地址分发）：

| 地址 | 字段 | 下界 | 上界 | 为什么 |
| --- | --- | --- | --- | --- |
| `0x40` | ci | 0 | 423 | 超过 18 kHz 无意义（tan 会过 Nyquist） |
| `0x40` | res | 0 | 255 | 掩码内 |
| `0x44` | rate | 0 | 20000 | 20 Hz |
| `0x44` | depth | 0 | 255 | 掩码内 |
| `0x84` | gain | 0 | **`0x10000`(1.0)** | >1.0 会让延迟写截断并留在显存里 |
| `0x8C` | feedback | 0 | **`0x7333`(0.9)** | ≥1.0 自激跑飞 |
| `0x8C` | reverb_mix | 0 | `0x7FFF` | 同上 |
| `0x90` | volume | 0 | `0x20000`(2.0) | 之后有饱和器 |
| `0x94` | attack_step | **1** | 65535 | 0 = 起音永不上升（有声部但永远静音） |
| `0x94` | decay_step | 0 | 65535 | 0 = 停在峰值，合法 |
| `0x98` | sustain_level | 0 | 65535 | 0 = 延音静音，合法 |
| `0x98` | release_step | **1** | 65535 | **0 = 包络永不归零 → `active[]` 不清 → `event_ready` 卡死，整条事件流停摆** |

`release_step=0` 那一条是这次评审最值钱的发现：它不是"静音"，而是**需要复位才能恢复的死锁**。

## 12. 预设：patch bank 与参数面的映射（用户 2026-11-01：先写下来，面积不够再说）

### 12.1 现状：一个没有消费者的参数仓库

`v2_patch_bank` 已经是完整的参数存储：4 family × 8 track，PATCH 20 / CALIBRATION 15 / RULE 7 /
CURSOR 5 个参数位，每个 index 有独立 MIN/MAX（`v2_patch_value_valid()` 是 10 位地址的大 case）、
CRC16 + 版本 + **APPLY 只在 idle / loop 边界发布**、`S_CRC / S_WAIT / S_COPY` 状态机齐备。
**但 `patch_active_value` 只走到 `0x50` 读回**（`mgc3130_v2_top.sv:1145`），音频与事件路径
一处都不读——所以今天它是"装好的枪，没有枪管"。

### 12.2 映射：一个 F0 index = 一个 CSR 字的原值

不做"一个参数一个 index"的细粒度映射（那要拆字段、载入逻辑更绕），而是**整字存、整字载**：

| F0 index | 对应的 CSR | 内容 |
| --- | --- | --- |
| `F0_I0` | `0x40 FILTER` | ci / res / enable |
| `F0_I1` | `0x44 LFO` | rate / depth / enable / retrig / unipolar / waveform |
| `F0_I2` | `0x84 FX_A` | gain / level / enable |
| `F0_I3` | `0x88 FX_B` | delay / cutoff |
| `F0_I4` | `0x8C FX_C` | feedback / reverb_mix |
| `F0_I5` | `0x90 VOLUME` | 主音量 |
| `F0_I6` | `0x94 ENV_AD` | attack / decay |
| `F0_I7` | `0x98 ENV_SR` | sustain / release |
| `F0_I8` | `0x9C VOICE_MIX` | velocity_depth / detune_shift / glide |
| `F0_I9..I19` | — | 留空（将来细分用） |

语义：**一个 track 的 F0_I0..I8 就是一套音色**（8 个 track 对应 8 套，和 4 条 LOOP 轨天然对齐）。

### 12.3 载入语义与优先级

1. `PATCH_APPLY` 成功后，等现有机制在 **idle 或 loop 边界**把 shadow 发布成 active；
2. 发布的**同一拍或下一拍**，用 `S_COPY` 的时机把 `active[F0_I0..I8]` 一次写进 9 个 live CSR
   寄存器（9 个 load 使能，~40~60 LUT，无新状态机——`S_COPY` 已经在扫 index 了）；
3. **优先级：后写者赢**。APPLY 之后主机再单独写 `0x40` 等地址，就覆盖预设值，直到下一次 APPLY；
4. 载入会立刻改变正在发声的音色（这是预设的意义），但因为它发生在 loop 边界，听起来是"切音色"
   而不是"爆音"；旁路位在 `0x40[24]`/`0x44[24]` 里，所以一套预设也能定义"完全旁路"。

### 12.4 必须先解决的一件事：两处校验会打架

`v2_patch_value_valid()` 里 `F0_I0..I8` 的 MIN/MAX 是**旧设计留下的**（I0/I1 是 0..65535、
I2 是 ±307200、I5 是 0..32767、I8 是 0..3840……），与新参数的语义几乎全不匹配
（例如 `VOLUME` 需要 0..`0x20000`＝131072，而 `F0_I6` 的上限只有 10000）。
所以接线那天必须把这两处校验**收敛成一个来源**：

- 权威表 = 本文件 §11.6 的 clamp 表；
- `v2_patch_value_valid()` 对 `F0_I0..I8` 改成"**掩码测试**"（`value & ~mask == 0`）再套 clamp，
  不再用旧的区间；
- 否则会出现"CSR 里是 0.9、载入预设后变 1.9"这种怪事（feedback 就是现成的例子）。

### 12.5 本轮不做，以及面积不够时怎么办

- **P2a / P2b 都不接**这条线：它们各自已经够大（§11.4），而且参数面还没稳定就做预设是白做；
- 这算**P2c（接线轮）**：约 40~60 LUT + 改一张校验表 + 一个 tb（APPLY 后 9 个 CSR 读回等于预设值）；
- **面积不够时**：按用户 2026-11-01 的话"再说"。若那时决定不做预设，**删掉 patch bank 换面积**
  是最省的一刀（记录估算 ~763 LUT / 261 reg / 4 BSRAM，其中相当一部分是那张 10 位地址校验 case），
  代价是永远没有预设；若决定做，就按 §12.2 接。**这两条都不在本轮执行**，写在这里只是免得以后重想。
