## 1. 意图与为什么

控制面现在散在三处：15 个 `scripts/board_*.ps1`、7 个构建脚本、一个只能画光标的
`host/cursor_view.py`。板子最新一轮（P2a + P2b）第一次有了**可调的音频链**：滤波、LFO、
效果器、主音量、包络四段、力度深度、失谐宽度、滑音。但这些参数**没有任何地方能组织成一个声音**：
调完就丢，换个回合从复位值重来，听感验收结论也没法对应到具体寄存器值。

同时 patch bank 已删除（`9df56d2`），`0x48–0x5C` 回 `BAD_ADDRESS(0x02)`，片上不再存预设。
**预设必然住在主机侧**——这不是选择，是删除后的唯一去处。

所以这个控制台要回答一个具体问题：*听到一个声音之后，怎么把它完整地存下来、下次一模一样地放回去。*

## 2. 目标 / 非目标 / 反目标

### 2.1 目标

1. 一个窗口完成：连接 → 上传波表 → 调音色 → 存预设 → 演奏 → 录 loop → 回放。
2. 预设可存盘、可进仓库 review、可从板子反向抓取。
3. 每次写入都读回**有效值**（因为契约是 clamp，不是 NACK）。
4. 每个实时视图的数据源都写清楚（遥测帧 / 调试寄存器 / 命令读回），不靠猜。

### 2.2 非目标（v1 明确不做）

- **不做电平表**：PEAK/RMS 的原地址已被 `0x84–0x90` 占用，补电平要新地址 + RTL，v1 不碰 RTL。
- **不做手机 App / 蓝牙**：传输层留端口抽象，v1 只验 USB `COM4`；HC-05 只作为未来端口。
- **不做 GAO、构建、烧录、回归**：这些留在脚本，控制台不接管。
- **不做鼠标绘制波形**：波表页只显示、选帧、上传、读回比对。
- 不暴露 `0x10 PLAY`、`0x2C RESET`（顶层未实现），也不给已删除的 patch 区留任何控件。

### 2.3 反目标

- 一个"什么都能点、点了不生效"的控制台。作用域（LIVE / PLAY / 三路）必须显示在控件上。
- 把用户输入的值显示成"当前值"。clamp 之后读回什么就显示什么。
- 用"有声部"冒充"有声音"。没有电平证据时，界面不许写"正在发声"。

## 3. 约束（全部来自代码或实测，不是估计）

### 3.1 传输

| 事实 | 来源 |
| --- | --- |
| 命令帧 11 B、应答/遥测帧 22 B，CRC16-CCITT-FALSE（init `0xFFFF`） | `host-tools-and-gui-controls.md` §2 |
| **一条命令等 ACK = 17.0 ms**（30 次：16.91–17.05） | 2026-11-01 实测（本机 COM4） |
| 流水线 ≥280 µs 节拍：400/400 全收；200 µs：349/400 | 同上 |
| ACK 优先于遥测帧，遥测不会挡命令 | `mgc3130_v2_top.sv:1362` |
| 链路同时只允许一个 outstanding，回复期间收到的帧会被丢 | `v2_uart_link.sv:228` |
| 串口独占（`cursor_view.py` 开着就抢不到） | HANDOFF §3 |

**推论**：预设 9 条写，流水线约 **2.7 ms**；顺序等 ACK 是 **153 ms**。控制台必须走流水线，
否则"九条写约 2 ms"（HANDOFF §6.3）这句话在实现里根本不成立。

### 3.2 参数面

- 写入 clamp：掩码**内**越界值被夹住、写入成功、读回是夹后值；掩码**外**的位被链路判
  `BAD_DATA(0x07)` 并 NACK，寄存器不变（`v2_contract_pkg.sv:345-414`）。
- `0x40 FILTER`、`0x44 LFO`、`0x90 VOLUME` 作用于**三路**（mux 之后）。
- `0x84–0x8C FX` **只作用于 PLAY**；`0x94/0x98/0x9C` **只作用于 PLAY 的 32 声部**。
- `FX_A` 复位 `0x0015_0000`（板上 `FX_ENABLE=1 FX_LEVEL=1`）；**增益写 0 会让 PLAY 变哑**，
  且增益与截止不受 `[20]` 使能管。
- `fx_level`（`FX_A[19:18]`）不是"4 档互斥链条"，而是**累积叠加**：1 = +低通，2 = 再 +延迟，
  3 = 再 +梳状×混合（`v2_fx_lite.sv:107-110`）。四轨在 level 3 会削顶成直流 = 静音。
- 复位值可当连接自检：`0x94=0x0100_1000`、`0x98=0x0400_C000`、`0x9C=0x0200_0000`。
- 两个"死锁"值由契约夹到 1：`attack_step=0`（起音永不上升）、`release_step=0`
  （包络永不归零 → `active[]` 不清 → 事件流停摆）。界面必须提示"你输入的值会被改"。

### 3.3 资源

本设计**不改 RTL**，所以 CLS 10750/11520、DSP 28/28 的余量问题与它无关。

## 5. 参数模型

9 个寄存器 = 9 个参数对象。每个对象带：地址、掩码、位段、单位换算、clamp 区间、复位值、作用域。

| 地址 | 名字 | 字段 | 界面单位 | 范围 | 作用域 | 危险 |
| --- | --- | --- | --- | --- | --- | --- |
| `0x40` | FILTER | `[11:0]` ci · `[19:12]` res · `[24]` enable | `fc = 40·2^(ci/48)` Hz（4 极点 −3 dB ≈ `0.43·fc`）；res 0–255（0–28 dB） | ci ≤ 423（≈17.9 kHz）、res ≤ 255 | 三路 | 默认 0 = 旁路 |
| `0x44` | LFO | `[15:0]` rate mHz · `[23:16]` depth · `[24]` en · `[25]` retrig · `[26]` unipolar · `[29:27]` wave | 0.05–20 Hz；深度 0–255 ci（255 = ±5.3 八度）；波形 5 选 1 | rate ≤ 20000 | 三路 | — |
| `0x84` | FX_A | `[17:0]` gain Q16 · `[19:18]` level · `[20]` en | 档位 0–3，**累积不是互斥**：1 = +低通，2 = 再叠延迟，3 = 再叠梳状×混合 | gain ≤ `0x10000` | **仅 PLAY** | **gain=0 → 哑；level ≥2 四轨会削顶成直流 = 静音** |
| `0x88` | FX_B | `[9:0]` delay · `[31:16]` cutoff Q16 | 延迟 = 值 + 1 拍（0–1024 采样） | 无 clamp | 仅 PLAY | — |
| `0x8C` | FX_C | `[15:0]` feedback Q15 · `[31:16]` mix Q15 | 0–0.9；0–0.9999 | feedback ≤ `0x7333`、mix ≤ `0x7FFF` | 仅 PLAY | ≥1.0 自激 |
| `0x90` | VOLUME | `[17:0]` Q1.16 | dB（`0x10000`=0 dB，上限 +6 dB） | ≤ `0x20000` | 三路 | 之后有饱和器 |
| `0x94` | ENV_AD | `[15:0]` attack_step · `[31:16]` decay_step | 时间 = `65535/step/48` ms（step 越大越快；4096 → 0.33 ms，1 → 1365 ms） | attack ≥ 1 | 仅 PLAY | attack=0 夹到 1 |
| `0x98` | ENV_SR | `[15:0]` sustain · `[31:16]` release_step | sustain 0–1.0；release 时间同 attack 公式 | release ≥ 1 | 仅 PLAY | **release=0 死锁**，夹到 1 |
| `0x9C` | VOICE_MIX | `[1:0]` velocity_shift · `[3:2]` detune_shift · `[31:16]` glide_rate | 各 0–3 档；glide 越大越快 | glide ≥ 1 | 32 声部；**LOOP 事件不带力度 → velocity_shift 实际只在 LIVE 听得出** | glide=0 夹到 1 |

**三条实现规则**

1. 写 → **读回** → 显示有效值；输入值与读回值不同的时候，界面标注"已 clamp"。
2. 滑杆拖动**只写不读**，按 **20–30 Hz 合流**只发最新值；松手时读回一次，与本地按 `params.py`
   预测的 clamp 值比对（见 §14.3）。单次往返 17 ms，不能每帧都发。
3. 作用域不符的控件（例如 LIVE 里拧包络）显示为灰色并注明"只影响 PLAY"。

## 6. 预设

### 6.1 文件

`host/presets/<name>.json`，进仓库。`words` 存的是**读回校验过的有效值**（clamp 之后，
见 §14.6），另带波表身份（§14.4）：

```json
{
  "schema": 1,
  "name": "warm-pad",
  "notes": "attack 慢，detune 窄",
  "created": "2026-11-02",
  "bitstream": {"run": "v2_board_top_p2b_no_patch", "sha256": "471fa9ba4b2878c0…"},
  "wavetable": {"table": 0, "version": 3, "crc": 43609, "voice_shift": 2, "morph": false},
  "words": {
    "0x40": 268438016,
    "0x44": 0,
    "0x84": 1376256,
    "0x88": 4294901760,
    "0x8C": 0,
    "0x90": 65536,
    "0x94": 16781312,
    "0x98": 67108864,
    "0x9C": 33554432
  }
}
```

`words` 存的是**寄存器原值**，不是滑杆位置——换算只在界面层做，预设文件永远能直接回放。
`bitstream` 记下抓取时的位流 sha256，避免"参数一样但固件不同"的假对比。

### 6.2 应用顺序

**按地址升序，一条一条写、每条读回**——这正是 `scripts/board_tune.ps1`（`98f9471`）已经在板上
验证过的做法，没有理由换一个没验过的顺序：

`0x40 → 0x44 → 0x84 → 0x88 → 0x8C → 0x90 → 0x94 → 0x98 → 0x9C`

顺序本身不是安全机制；安全机制是**逐条 write → readback → 不一致即抛错**。
唯一需要额外守卫的是 `FX_A` 的增益为 0（会把 PLAY 变哑），写前拦下并说明。

流水线 9 条约 2.7 ms 传输 + 一次约 17 ms 的驱动窗口 ≈ **20 ms 墙钟**。
任何一条被 NACK 或读回不符，**中止并保留其余不动**，界面显示哪一条失败。

### 6.3 操作

- **应用**：写 9 条 → 逐条读回 → 与文件比对，不一致就标红（失败）。
- **波表身份只警告不拒绝**（2026-11-02 修正）：`board_tune.ps1` 的四个预设对任何表都能应用，
  九个字与表无关；所以表/版本不符时**显著提示**"这不是当初那张表"，但仍允许应用。
- **抓取**：读 9 个字生成新预设（`0x84` 连带读档位）。
- **另存 / 重命名 / 删除**：只动 JSON。
- **A/B**：两个槽，一键切换，每次切换写一行会话日志（带时间戳与当前模式）。

## 7. 界面结构

单窗口，三栏：

```
┌ 连接条 ── 端口/波特率 · 连接 · 身份灯(0xB0) · 模式灯(STATUS[2:0]) ─────────┐
├ 预设列表 ──┬ 标签页：演奏 | 音色 | LOOP | 波表 ────────────┬ 状态 ───────┤
│ name       │                                              │ 模式/声部   │
│ name  ★    │  （每个标签页一个画布 + 一组控件）              │ 表/版本     │
│ …          │                                              │ 日志尾部    │
└────────────┴──────────────────────────────────────────────┴────────────┘
```

| 标签页 | 内容 | 数据源 |
| --- | --- | --- |
| 演奏 | 感应区（默认 flip y）+ 拖尾 + 四角参考；当前音/门/模式/声部数 | 遥测帧（period 240 = 200 Hz） |
| 音色 | 六块：滤波 / LFO / FX / 音量 / 包络 / 声部；每块带作用域标记 | 参数模型 + 读回 |
| LOOP | 32 点轮廓曲线、POTTS 状态、当前轨采集计数与本轮提交数、播放态；**录制前倒计时**；**不显示每轨矩阵**（§14.7）；**没有"清空"按钮**（§17.3） | `0x34`/`0x38`/`0xF8` 页 1/2 |
| 波表 | 三帧曲线（1024 点）、上传进度、读回差异高亮 | `WT_*` + 本地文件 |

## 8. 所有权与安全

1. 一个进程一个端口；打开前检查 `cursor_view.py` 是否在跑（同名进程检测失败就提示"先关掉别的"）。
2. 上传/写表强制 IDLE；进入前只发 `STOP`，**不要等 `STATUS[8]` 落 0**——`CLEAR_ALL` 从不把
   `loop_active_valid` 归零，等它只会挂住（`host-tools-and-gui-controls.md` §9.1）。
   当前唯一可靠的"清空 loop"是**重烧位流**；界面不提供假的清空按钮。
3. `PLAY` 中禁止 `WT_DATA` 读回（硬件返回 0，读回来是假数据）。
4. `STOP` 的 data 必须 **恰好 1**；`0x2C RESET` 不提供。
5. 进入遥测前写 `0x80`，**退出时写 `0x80 = 0`**（`board_cursor.ps1` 的坑：不关流会让下一个脚本
   报 `SEQ MISMATCH` + 254）。
6. 危险输入要二次确认：FX 增益 0、音量 > 1.0、`attack_step=0`、`release_step=0`、`glide_rate=0`
   （后三个会被 clamp，确认框说明"会被改成 1"）。
7. 关闭窗口时如果还在 PLAY，先 `STOP`，再关流，再关端口。

## 9. 证据与日志

- 每条命令与读回写 JSONL：`{"t": "...", "seq": 12, "op": 2, "addr": "0x40", "data": "0x0FF8", "err": 0}`。
- 听感验收结论必须能引用"位流 sha256 + 预设文件 + 这一行日志"。
- `--headless`：无显示器模式，回放录制的帧序列，供回归使用。

## 10. 验收

**无界面（自动）**
- CRC 自检 `0x29B1`；帧构造与解析（半帧、错 CRC、粘帧、`0x5A` 出现在数据里）；
- 参数换算（ci→Hz、step→ms、Q16→dB）与 clamp 表逐条对照契约包；
- 预设往返：读 → JSON → 写 → 读回一致；顺序与中止行为；
- 状态机非法序列（PLAY 中上传、未连接就应用）必须拒绝且不发出帧。

**板上（人工 + 记录）**
- 连接：`0xB0`、`STATUS`，以及三个复位值自检；
- 上传：与 `board_wt_upload.ps1` 输出的一致 CRC / apply 结果；读回 1024/1024；
- 预设应用：9 条全部 err=0，读回与 JSON 一致，且与 `board_tune.ps1 -Preset warm` 的输出逐字相同；
- LOOP：与 `board_stage2_loop.ps1` 的提交计数、发布、STOP 静音逐项对齐。

## 11. 风险

| 风险 | 对策 |
| --- | --- |
| 单次 17 ms 往返让"点一下立刻听到"不可能 | 交互文案不承诺即时；滑杆 20–30 Hz 合流；批量操作用流水线 |
| 9 字无原子性 | 固定顺序 + 中止即停 + 读回比对 |
| clamp 让"写入成功"≠"值等于输入" | 永远显示读回值，并标"已 clamp" |
| Tk 密集面板刷新 | 只重绘变化的画布元素，遥测按 20–30 Hz 合并 |
| 预设格式进仓库后有兼容负担 | `schema` 字段 + 读旧版时只做加法 |
| 听感验收仍然只能靠耳朵 | 预设文件 + JSONL 让"这一版声音"可复现，不再回到"有声部≠有声音" |

## 14. 评审答复（2026-11-02，九条）

评审以"要照着这份文档写计划的人"的视角提出九条。七条在这里定案，一条并入 §16 待用户拍板。

### 14.1 传输策略

- **允许流水线**，节拍取 **320 µs**（实测 280/350/450 µs 全部被接受，200 µs 掉包 51/400，取偏安全的一侧）。
- **1024 点上传与读回允许作为突发**：按节拍发送，回复事后审计（seq 配对、逐条 err）。
  但这是**读路径**上量出来的性质，写路径（`WT_DATA`）未验 → 计划里加一个前置任务：先用 1024 次
  `0x68` 写实测节拍，不通过就退回逐条等 ACK（脚本日志里 1028 条 = **18.3 s**，`artifacts/board/wt_upload.log`）。
- **丢失回复**：用**相同 seq、相同字节**重发一次。链路的重复帧缓存会重放上一次的回复
  （`v2_uart_link.sv:233-243`），所以重发是恰好一次，不是二次执行。重发仍无回复 → **中止整个工作流**，不猜。
- **"九条写 2.7 ms" 是传输时间**，不是墙钟：主机还要付一次约 17 ms 的驱动窗口，实测预期 **≈ 20 ms**。
  这条更正写进 §6.2。

### 14.2 模式所有权

- **不提供自由模式下拉**。只有三个显式动作：**演奏**（`MODE=1`，或 `MODE=6` 走表）、**回放**（`MODE=4`）、**停止**（`STOP=1`）。
- 录制**不写 `MODE=2`**：`0x18` 的 arm 完成后硬件自己把 `mode_reg <= RECORD`（`mgc3130_v2_top.sv:1414-1417`）。
  控制台只发 `0x0C`（选轨）与 `0x18`（arm）。
- **切标签页永不改模式**：点开"音色"页不会停掉正在播的 loop。
- 九个参数在 PLAY 中可写（RTL 不 gate，`top.sv:1446-1466`），所以"边播边调"是支持的；
  界面只对真正需要 IDLE 的动作（上传、读回）加锁。

### 14.3 读回节奏

§5 的两条规则不是二选一：

| 场景 | 行为 |
| --- | --- |
| 拖动滑杆 | 只写不读（20–30 Hz 合流），界面显示本地按 `params.py` 预测的 clamp 值 |
| 松手 / 点"发送" | 读回一次，与预测比对；不同则标"已 clamp 为 X" |
| 应用预设 / 抓取 | 每一条都读回并记录 |
| 演奏页的 gate / 模式 / 声部数 | 不在遥测帧里 → 每 100 ms 轮询 `0xE8` 与 `0x00`（两条流水线发送，占一次 17 ms 窗口） |

### 14.4 预设的内容边界

预设 = 九个字 + **波表身份**（table id、`WT_VERSION`、`WT_CRC`、voice shift、morph 位）+ 备注 + 位流。

- 应用前读 `WT_STATUS` 与 `WT_SELECT`；版本或 CRC 不符 → 弹"表不匹配（板上有 vX，预设基于 vY）"，
  **默认拒绝**，另给一个显式的"仍然应用"。
- 这把 §1 的"一模一样"从九个字扩到"九字 + 那面波表"。**这是我替你定的，可推翻。**

### 14.5 位流 sha256 的来源

板上读不到：`0xB0` 只是常量 `0x5A5A0003`，P1/P2a/P2b 都一样。控制台在连接时让操作者从 `impl/*/`
选本次烧录的 run（记住上次选择），从 `synth_summary.json` 取 sha256 写进会话与预设。
不匹配只警告，不阻止——板子无法自证。

### 14.6 预设存有效值

JSON 存**读回校验过的有效值**（clamp 之后）。理由：只有有效值能保证"放回去还是一样"。
用户输入的意图值只活在界面内存里（用于拖动与撤销）；读回不同就显示"已 clamp 为 X"。
因此 §6.3 的"clamp 或失败"改为"读回不一致 = 失败"，§10 的"读回与 JSON 一致"才成立。

### 14.7 per-track 计数

硬件只暴露两个 6 位字段，而且 **`0xF8` page 1 对所有轨读回同一个字**（四轨实测都是 `0x0060008B`，
`host-tools-and-gui-controls.md` §9.7），已发布 bank 的事件读不出来。所以 **LOOP 页不做每轨矩阵**，只显示当前轨。
"本次会话提交了哪几轨"由控制台自己的命令日志维护；连到一个不是它录的 loop 时显示"未知（非本会话录制）"。

### 14.8 headless 与 fixture

两层都要：JSONL 是证据；`link.py` **从第一天就带字节级 trace 钩子**（`--trace bytes.jsonl`），
回归用真实字节流做 fixture（先手采四段：连接、读身份、应用预设、起遥测）。
回放目标是 `FakePort` 喂字节，断言解析与工作流，不碰硬件。

## 15. 两个不必回答、但必须写进代码的陷阱

1. **遥测只在光标有效时出帧**（`top.sv:1572`，`audio_cursor_valid`）。流是静的时候，多半是手不在感应区，
   不是链路死了。界面要有"等待光标"态，不能报"串口无数据"。
2. **上传必须照抄脚本的版本舞步**：从 `WT_STATUS[15:0]` 取当前活跃版本作为期望版本
   （自己 `+1` 会三方不匹配，必被拒）；上传完成后**必须**把 `WT_SELECT` 连同声部移位写回
   （今天的日志用 `PostSelect=0x20`），否则整块表小 12 dB。

## 16. 仍待用户拍板

**LOOP 页的定位**：控制台是"能录、能提交、能发布"的控制面，还是只做监视与回放？
若做控制面，必须决定录制语义——RTL 提供 `0x18`（PREPARE_RECORD，替换）与 `0x1C`（PREPARE_OVERDUB，叠加），
且今天的验收脚本走的是**破坏性**开始（`STOP → CLEAR_ALL → MODE=PLAY 发布空 bank → STOP`），
这会清掉板上已有的 loop。这一条决定 LOOP 页的任务量（约占总量的三分之一）。

> **2026-11-02 晚更新（已部分回答）**：那个"破坏性开始"现在被证明**不成立**——
> `CLEAR_ALL` 从不把 `loop_active_valid` 归零，清场只在板上本来就空时才能过（`§17.3`）。
> 而"录制"本身是**逐轨叠加**：在已发布的 4 轨 take 上重录 track 2，其余三轨保留、`voices=3`（板上实测）。
> 所以剩下的真问题只有一个：**要不要给"叠加（overdub，0x1C）"按钮**——它在 RTL 里但从未上板验证过。

### 17.1 被推翻的三条

| 旧结论（本文档曾写） | 实际 | 现在改在 |
| --- | --- | --- |
| FX 档位是"4 档链条选择"（干/低通/延迟/梳状） | `level≥2` 是 `lp + 延迟数据`，`level≥3` 再 `+ 梳状×混合`（`v2_fx_lite.sv:107-110`）；**四轨叠加后削顶成直流 = 静音** | §5 的 FX 行 |
| 预设要"钉住波表、版本不符就拒绝应用" | 九个字与表无关，`board_tune.ps1` 的四个预设对任何表都能应用 | §6.3：只警告不拒绝 |
| 清场靠 `STOP → CLEAR_ALL → 发布空 bank` | `CLEAR_ALL` 只清 shadow，**从不置 `loop_active_valid=0`**；该等待只在板上本来就空时成立 | §8.2、§17.3 |

### 17.2 预设已经存在，不是待做的功能

`scripts/board_tune.ps1`（`98f9471`）已经实现"名字 → 九个字 → 逐条写 → 逐条读回验证"，
四个预设：`warm` / `pluck` / `space` / `flat`（`flat` = 全默认，用于 A/B）。

- 控制台**导入这四个字组作为种子预设**，不重新推导；
- 验收判据：控制台应用 `warm` 之后的九条读回，与 `board_tune.ps1 -Preset warm` 的输出**逐字相同**；
- `space` 目前的定义在四轨上会把音频削成直流（§9.6），导入时标"仅低轨数"或直接把档位降到 2。

### 17.3 没有可靠的"清空 loop"

唯一可靠的清空是**重烧位流**（SRAM 配置会清掉 loop 状态）。所以：

- LOOP 页**不提供"清空"按钮**——它要么失败要么骗人；
- 需要空白起点时，界面给出"重烧位流"的操作指引，而不是发一个假装能清的 `0x24`；
- 录制**不需要**清场：`PREPARE_RECORD` 会 `copy_active`，其它轨保留。

### 17.4 录制是"盲录"

`loop_event_ready` 与 `voice_rst_n` 只在 `mode_play` 使能（`mgc3130_v2_top.sv:562/565`），
进 RECORD 声部引擎被复位 → **录制时听不到已有轨**。真正的 overdub 监听要改 RTL（P3，约 770 CLS 余量）。

界面必须这样表达：录制中显示"盲录中——听不到其它轨"，并在 arm 前给 **3 秒倒计时**
（对应脚本的 `-PrepareSeconds`，`bd58d4f`），否则轨 1 会在轨 0 发布后约 4 秒悄悄开始。

### 17.5 十条脚本坑 → 控制台行为

`host-tools-and-gui-controls.md` §9 的十条，逐条落到界面或代码：

| 条目 | 控制台怎么做 |
| --- | --- |
| 9.1 清场前提 | 不提供清空；只 `STOP`，不等 `STATUS[8]` |
| 9.2 轨间无准备时间 | arm 前 3 秒倒计时 + "手在感应区"提示 |
| 9.3 0/32 的两种原因 | 录制无数据时自动做判据：读 `0xEC` 两次（在涨=传感器活）、`0xDC raw_x`、`0xE0 raw_z < 30000` |
| 9.4 先写后打印 | 每次"发送"都是写 → 读回 → 再更新界面 |
| 9.5 端口独占 | 一个进程一个端口；上传前释放，结束后 `finally` 关闭 |
| 9.6 FX 削顶 | 档位 ≥2 时显示增益预算警告；预设导入时检查 |
| 9.7 每轨计数读不回 | 不做矩阵；只显当前轨 + 本次会话记录 |
| 9.8 PowerShell 坑 | 控制台是 Python，不受影响；但脚本仍在用，文档保留 |
| 9.9 加轨/改单轨 | 直接 CSR 时序：`STOP → 0x0C → 0x18 → 0x3C → 等 0x38 bit4 → 0x28 → 等 bit0 → 0x04=4` |

### 17.6 增益预算（不是电平证据）

`98f9471` 记录的可用组合：手绘表峰值 29490 × `WT_SELECT` shift 3（÷8）× PLAY 的 −12 dB × 主音量 1.5。
控制台可以在预设里存 `voice_shift` 并显示一条**估算**的增益链（表峰值 × 2^-shift × fx × volume），
标清"这是算术，不是测量"——真正的电平证据仍然只能靠 GAO。
