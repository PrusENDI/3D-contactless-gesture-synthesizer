## 1. 意图与为什么

演示要产出"能听的四轨片段"，而现在的失败模式有两个，都是**结构性的**，也都已被用户确认：

1. **整段有空档**：轮廓每个 tick 存的是 `y[15:6]`，且必须 `engaged`（`v2_loop_contour_capture.sv:55-56`）。
   手离开感应区的那几个 tick 就变成休止。实测同一次 4 轨录制里既有 32/32，也有 23/32、27/32。
2. **几条轨的音高互相不搭**：音高只有 8 个值（`v2_note_increment_rom.sv`：`55/57/60/62/64/67/69/72`，
   **`default: increment = 0`**，其它音号静音），四条轨落在同一音区或相邻级上就会糊。

两者共同的原因：**录制是盲录**——`loop_event_ready` 与 `voice_rst_n` 只在 `mode_play` 使能
（`mgc3130_v2_top.sv:562/565`），进 RECORD 声部引擎被复位，操作者听不到已有轨。
没有 overdub 监听，就必须**用眼睛替代耳朵**：把已录的轨迹画出来，让操作者把自己的线画进空位。

所以本设计回答：*在没有监听的情况下，怎么让每一次录制都可预测、可校验、可重试，并且四条轨听起来是"一组"。*

## 2. 目标 / 非目标 / 反目标

### 2.1 目标

1. **一块画布体系**：LIVE / LOOP / 波表三块**各自独立**的 Canvas，共用同一套归一化坐标与同一套绘制代码。
2. **LOOP 页滚动显示**：32 tick 为横轴、8 条音高档为纵轴；本次会话已录的轨画成静态曲线，
   正在录的那一轨实时画上去。
3. **辅助录制**：强制小节 → 倒计时 → arm → 覆盖门禁（提交前判定）→ 撞音检查 → 提交 → 发布，
   全程有可视反馈，失败可一键重录。
4. 以上全部**无需显示器即可测试**（绘制器输出显示列表）。
5. 不改 RTL。

### 2.2 非目标（v1 明确不做）

- **不改 RTL 做 DAC 侧的 overdub 监听**（`0x1C PREPARE_OVERDUB` 在 RTL 里但从未上板验证；
  `voice_rst_n`/`loop_event_ready` 加 `mode_record` 属于 P3，见 §14.1 的方案 B）。
  v1 用**主机侧参考音轨**替代（§7.5，用户 2026-11-02 选定）。
- **不做示波器/电平表**：仍然没有 `i2s_sample` 的读回通路（要 GAO）。
- **不做音符编辑**：主机不能注入或改写 loop 事件（没有写入口），本设计只做引导、判定与重录。
- **不做自动编曲**：不替操作者决定旋律，只在提交前给出"会撞"的提示。
- **不做多窗口**：三块画布在同一个单窗口的三个标签页里（父设计 §7）。

### 2.3 反目标

- 一个"看起来在滚但和实际 tick 不同步"的动画。同步不确定时，宁可标注"未对齐"，不许假装对齐。
- 把覆盖判定做成"提交后警告"。空档必须在**提交前**拦下，提交后已经进 shadow 了。
- 让撞音检查**阻止**提交。它只是建议：音乐上"撞"有时正是想要的效果。
- 用"有声部"冒充"有声音"（父设计 §2.3 的同一条）。

## 5. 共用坐标与图元

### 5.1 归一化坐标

绘制与断言都在 `(u, v) ∈ [0,1]²` 里，**v 向上**（与数学坐标一致），渲染器负责翻成屏幕像素。
**变换吃的是"已做过 flip 的坐标"**；`apply_flip` 是调用方（采集层）的责任，绘制器不碰 flip。

| 视图 | u | v | 说明 |
| --- | --- | --- | --- |
| LIVE | `x/65535` | `1 − y/65535` | `x,y` 已过 `apply_flip(..., flip='y')`（C14）；四角与十字由渲染器画 |
| LOOP | `tick/31` | `contour/1023` | 音高随 y 升高，与 LIVE 行同向（C3）；叠加 8 条音高档 |
| 波表 | `i/1023` | `(1 + sample)/2` | `sample` 归一化到 −1..+1（C15） |

### 5.2 显示列表图元

绘制器返回一个 `Drawing`：**有序的图元列表**，每个图元都带 `layer`，取值只有三个名字，按此顺序绘制：
`static`（已录轨、音高档、网格）→ `loop_live`（播放头、正在录的线）→ `live`（光标点与拖尾）。

| 图元 | 字段 | 用途 |
| --- | --- | --- |
| `Path` | `points: [(u,v)]`, `closed`, `width`, `color_key`, `layer` | 轨迹、曲线、轮廓 |
| `Band` | `u0,u1,v0,v1`, `color_key`, `label`, `layer` | 8 条音高档、播放头区间、空档告警 |
| `Marker` | `u,v`, `shape`, `label`, `layer` | 光标点、四角参考、当前 tick |
| `Text` | `u,v`, `text`, `anchor`, `layer` | 轴标签、音名（G3…C5） |
| `Grid` | `n_u, n_v`, `layer` | 十字、tick 网格 |

`color_key` 是**语义名**（`track0..track3`、`live`、`bands`、`grid`、`warn`），渲染器映射到具体颜色。

### 5.3 三条实现规则

1. **绘制器不许 import tkinter**：只接受数据、返回 `Drawing`。渲染器是唯一碰 Tk 的地方。
2. **渲染器按 layer 重画**：`loop_live` 每帧（20–30 Hz），`static` 只在数据变化时重建，`live` 每帧。
3. **坐标断言用显示列表，不用像素**。

## 6. LOOP 滚动视图

### 6.1 内容

- 横轴 32 tick（u = tick/31），每 tick 一格；纵轴 8 条音高档（G3/A3/C4/D4/E4/G4/A4/C5）。
- **本次会话录过的轨**：每轨**每条连续 engaged 段一条 `Path`**（手离开就断），颜色 `trackN`，`static` 层。
- **正在录的那一轨**：同样按连续段画，实时追加末端点（`loop_live` 层）。
  注意：遥测是 200 Hz 的 y，而轮廓是一个 tick 一个 y，所以**实时线的 u 来自相位估计**，
  它不会与提交后读回的 32 个点逐点相等——这一点在界面上以"实时（估计）"标注。
- **播放头**：一条竖线 `Marker`，按 §6.2 的相位前进。
- 顶部显示当前轨、覆盖率（非零 tick / 32）、以及"盲录中：听不到其它轨"。

### 6.2 相位（已定：锚定 + 强制小节）

**tick 读不回来**（C16），所以相位靠锚定：

1. **进入 LOOP 页或开始录制前，先写 `0x08=120`**（C2/C17）：BPM 被钉在 120，且非 LIVE 时小节从 tick 0 重开
   → 记 `t0 = now`，相位 `= ((monotonic() − t0) / 4.000) mod 1`。
2. **发布后重锚**：`0xF8` 页 1 的 bit6（commit pending）由 1→0 即"已发布"，那是唯一的发布可观测点
   （C8 说明不能用每轨计数）。此后的播放以该时刻为新 `t0`。
3. **漂移预算**：主机与 48 kHz 相对误差按 1e-4，每 4 秒 0.4 ms = **0.0032 tick**；
   5 分钟 0.24 tick。
4. **真正的误差不是漂移而是观测**：锚点只能通过一次 17 ms 的命令往返获得（C11）→ **±0.14 tick（≈18 ms）**，
   比漂移大 45 倍。**接受**：画面上滚动线最多比实际早/晚 1/7 格，对"跟着走"没有影响。
   为此**不加 tick 读回**（那要改 RTL，与 §2.1 第 5 条冲突）。
5. **"重新对齐"按钮 = 再写一次 `0x08=120`**（强制小节重开），不是"等下一次 0 位"——后者在纯播放时不可观测。

### 6.3 为什么滚动值得做

盲录时操作者需要知道"我现在在循环的哪一段"。静态 32 格只能事后看；滚动版能让操作者**跟着已有曲线走**，
这就是没有 overdub 时的替代品。

## 7. 辅助录制工作流

### 7.1 状态机

```
idle ──选轨/预设──> ready ──写 0x08=120（强制小节）──> countdown(3s)
countdown ──0x18 arm──> armed（显示"已武装，等小节起点"，最多等 1 个循环，C18）
armed ──第一个 tick 0 写入──> capturing
capturing ──0x38 bit4 置位──> captured ──0x34=0 后读 32 个样本──> analysing
analysing ──覆盖<30 且重试<2──> countdown（自动重录，注明原因）
analysing ──覆盖≥30──> reviewed（撞音提示，等操作者确认）
reviewed ──0x28──> committing ──0x38 bit0──> publishing ──0x04=4 到边界──> rolled
rolled ──下一轨──> ready
```

- `0x3C` lambda **不用写**：复位值已是 21600（C19）。
- 每一步写 JSONL（父设计 §9），"这一版片段" = 位流 sha + 预设 + 命令日志。

### 7.2 覆盖门禁（提交前，硬性）

- **先写 `0x34=0`**，再连续读 `0x34` 32 次（C4）→ 数 `!= 0` 的样本数 `nz`。
- `nz ≥ 30`：通过。
- `nz < 30`：**不提交**，把缺口画成 `Band(tick, tick+1, 0..1, 'warn', static)`，回到 countdown 自动重录
  （最多 2 次）。三次都失败 → 停下并诊断：读 `0xEC` 两次（帧计数在涨 = 传感器活）、`0xDC raw_x`、
  `0xE0 raw_z`（`< 30000` = 手在 engage 阈值内）。
- **已知边界**：硬件覆盖判据是 `valid_mask`（C1），而 `sample == 0` 也可能来自"engaged 但 y < 64"。
  本设计接受这个混淆：`nz` 偏小 → 只是多一次重录，不会漏判。

### 7.3 撞音检查（提交前，建议性）

- **y → 音号的映射不需要上板**（C3）：规则引擎阈值把 y 折成 8 个音级，DP 的拟合用 `LEVELS`(30..978) 与
  `NOTES`(55..72)。主机用 `host/v2_potts_reference.py`（确定性定点参考，与硬件同表）从 32 个轮廓值算出
  **每段拟合出的音**。
- 与本次会话其它轨的音级集合比较，三类提示：
  - **同音级**（两轨落在同一档）→ "会和 track N 撞在一起，建议换音区"；
  - **相邻音级**（档位相邻）→ "相邻档会摩擦"。**不做乐理断言**：相邻档实际相差 2–3 个半音，一半是三度；
  - 三全音不在本音表内，规则保留但不会触发。
- **只提示不阻止**。且提示基于"逐段拟合"的结果，不是逐 tick 猜测；若操作者只看画布，
  界面同时给出"估计使用音级"的区间色带。

### 7.4 每轨音色

提交后可为该轨单独套一套九个参数（父设计 §6）。界面是"轨 N 的预设"下拉，默认继承当前全局预设。
`0x84 level≥2` 有削顶风险（C13）：超过 2 轨时给增益预算提示。

### 7.5 参考音轨（主机侧 overdub 替代，v1 必做）

盲录时 FPGA 是静音的（C10），所以**录制期间 PC 声卡可以独占出声**——这就是不改 RTL 也能拿到监听的根据。

- **数据来源**：本次会话每录一轨，主机保留它提交前的 32 个轮廓值；`host/v2_potts_reference.py`
  （确定性定点参考，`LEVELS`/`NOTES` 与硬件同表）把它们解成"每段一个音 + 起止 tick"。
- **音高**：直接用 `v2_note_increment_rom` 的增量反算频率（`f = increment/2^32 · 48000`），
  所以参考音轨的音高与硬件**逐赫兹一致**，不是近似。
- **音色**：用当前上传的那份波表文件（1024 点）+ `WT_SELECT` 的移位增益，按段做最简单的重采样播放。
- **包络**：套用寄存器当前的 `0x94`/`0x98`（attack/decay/sustain/release 的 step 语义），
  与硬件同一套换算。
- **渲染与播放**：把**一个小节（4 秒）**渲成 WAV，用标准库 `winsound.PlaySound(SND_FILENAME|SND_ASYNC|SND_LOOP)`
  循环播放——**零新依赖**（不引入 sounddevice/pyaudio）。
- **对齐**：在写 `0x08=120` 强制小节重开的那一瞬间启动 WAV，于是参考的 tick 0 与硬件的 tick 0 同起点。
  每次强制小节都重启动一次，漂移不会累积。
- **何时重渲**：某轨提交后、预设变更后、波表上传后。
- **v1 明确不做**：参考音轨不过滤波/FX（`0x40`/`0x44`/`0x84–0x8C` 对它的影响忽略），
  界面标注"参考（无效果）"。理由是 play-along 需要的是音高与时间，不是音色。
- **不承诺**：电平一致。参考音轨是引导，不是电平证据（父设计 §2.3 的同一条）。

- 三块画布**各自独立**（各自一个 `tk.Canvas`），共用 §5 的坐标与图元代码。
- LOOP 页控件：轨选择（0–3）、**录制**（含 3 秒倒计时）、重录、提交、发布、**重新对齐**（= 再写 `0x08=120`）、
  覆盖指示、"盲录中"提示；**没有"清空 loop"按钮**（C9）。
- **切标签页永不改模式、也不打断流程**（父设计 §14.2）；只有"冲突命令"才拒绝
  （例如录制中重新 arm、发布中再提交）。

## 9. 验收

**无界面（自动，pytest）**

1. 坐标：LIVE 变换**吃已 flip 的输入**——`(0,0)→(0,0)`、`(65535,65535)→(1,1)` 经 `1 − y/65535` 后为 `(1,0)`；
   `apply_flip('y')` 由采集层负责，绘制器不调用。
2. 绘制器：给定 32 个轮廓值（含一处 engaged=0）→ `Drawing` 含 **2 条 `Path`**（按连续段断），
   总点数 == engaged 数；8 个 `Band`；标签序列 == `["G3","A3","C4","D4","E4","G4","A4","C5"]`；
   第 3 个 Band 的 `label == "C4"` 且其 `v` 区间包住该段轮廓的 v 值。
3. 覆盖门禁：`nz=29` → 拒绝 + 重试计数 +1 + 出现 `Band(...,'warn', 'static')`；
   连续三次 `nz<30` → 进入诊断分支并读出三个诊断寄存器。
4. 撞音：两轨同档 → 出现 `warn` 与建议文案；不同档 → 无 `warn`；相邻档 → "相邻音级"文案（不含"二度"）。
5. 相位：给定 `t0` 与假时钟，`t0+4.0 → u≈0`、`t0+2.0 → u≈0.5`；断言"锚点观测误差 ≤0.15 tick"被文档化，
   漂移断言用 0.0032 tick/4 s。
6. 状态机：未 captured 就 commit、发布中再 commit → 拒绝且不发帧；**录制中切标签页 → 允许**，
   流程继续（§8）；切回后画布状态不变。
7. 实时线：给一串 200 Hz 的 y 与相位估计，断言线的 u 单调推进、断开处对应 `engaged=0`。
8. 参考音轨：给一段合成轮廓 + 假音频后端，断言（a）一个 4 秒 WAV 被渲出、样本数 == 48000×4；
   （b）每段的频率与 `v2_note_increment_rom` 的增量反算值相等（±1 Hz）；
   （c）重渲只在"提交/预设/波表变化"时发生，不是每帧。

**板上（人工，记录）**

8. 录一轨：倒计时可见、`armed` 提示出现过、覆盖读数与脚本 `contour has N/32` 一致、提交后 `0x38` bit0 置位。
9. 画布上的轨曲线与该轨提交后读回的 32 个值逐点一致（同一份数据两个消费者）。
10. 播放头与听感：在 4 秒循环上，竖线经过某一 tick 时听到的音符与曲线一致（人耳，记一次）。
