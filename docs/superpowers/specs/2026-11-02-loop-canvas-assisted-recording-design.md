## 1. 意图与为什么

演示要产出"能听的四轨片段"，而现在的失败模式有两个，都是**结构性的**，也都已被用户确认：

1. **整段有空档**：轮廓每个 tick 存的是 `y[15:6]`，且必须 `engaged`（`v2_loop_contour_capture.sv:55-56`）。
   手离开感应区的那几个 tick 就变成休止。实测同一次 4 轨录制里既有 32/32，也有 23/32、27/32。
2. **几条轨的音高互相不搭**：音高只有 8 个值（`v2_note_increment_rom.sv`：`55/57/60/62/64/67/69/72`，
   **`default: increment = 0`**，其它音号静音），四条轨落在同一音区或相邻级上就会糊。

两者共同的原因：**录制是盲录**——`loop_event_ready` 与 `voice_rst_n` 只在 `mode_play` 使能
（`mgc3130_v2_top.sv:562/565`），进 RECORD 声部引擎被复位，操作者听不到已有轨。
没有 overdub 监听，就必须**用眼睛替代耳朵**：把已录的轨迹画出来，让操作者把自己的线画进空位。

所以本设计回答：*在没有监听的情况下，怎么让每一次录制都可预测、可校验、可重试，并且四条轨听起来是"一组"。*

## 2. 目标 / 非目标 / 反目标

### 2.1 目标

1. **一块画布体系**：LIVE / LOOP / 波表三块**各自独立**的 Canvas，共用同一套归一化坐标与同一套绘制代码。
2. **LOOP 页滚动显示**：32 tick（4 秒）为横轴、8 条音高档为纵轴；本次会话已录的轨画成静态曲线，
   正在录的那一轨实时画上去。
3. **辅助录制**：倒计时 → arm → 覆盖门禁（提交前判定）→ 撞音检查 → 提交 → 发布，全程有可视反馈，失败可一键重录。
4. 以上全部**无需显示器即可测试**（绘制器输出显示列表）。
5. 不改 RTL。

### 2.2 非目标（v1 明确不做）

- **不做 overdub**：`0x1C PREPARE_OVERDUB` 在 RTL 里但从未上板验证，本设计不碰。
- **不做示波器/电平表**：仍然没有 `i2s_sample` 的读回通路（要 GAO）。
- **不做音符编辑**：主机不能注入或改写 loop 事件（没有写入口），本设计只做引导、判定与重录。
- **不做自动编曲**：不替操作者决定旋律，只在提交前给出"会撞"的提示。
- **不做多窗口**：三块画布在同一个单窗口的三个标签页里（父设计 §7）。

### 2.3 反目标

- 一个"看起来在滚但和实际 tick 不同步"的动画。同步不确定时，宁可标注"未对齐"，不许假装对齐。
- 把覆盖判定做成"提交后警告"。空档必须在**提交前**拦下，提交后已经进 shadow 了。
- 让撞音检查**阻止**提交。它只是建议：音乐上"撞"有时正是想要的效果。
- 用"有声部"冒充"有声音"（父设计 §2.3 的同一条）。

## 4. 方案（已选定 A）

用户 2026-11-02 在三条路线里选了 A。

| 路线 | 做法 | 取舍 |
| --- | --- | --- |
| **A（选定）** | 绘制器输出**显示列表**（归一化坐标的点/线/带/文字），Tk 渲染器只消费列表 | 三块画布天然一致；**无需显示器即可测**（断言列表）；将来出 PNG 只需加渲染器。代价：多一层间接；LOOP 实时项仍要 20–30 Hz 重画 |
| B | 离屏光栅（Pillow）后整块贴 `PhotoImage` | 滚动最省 item 变动、天然可存 PNG；但坐标断言变成像素断言（脆），且与 `cursor_view.py` 现有画风不一致 |
| C | matplotlib 嵌入（TkAgg） | 轴/网格现成；重依赖、30 Hz 下慢、光标叠加与四角标注要绕开它的坐标系 |

**A 的理由**：这个项目 90% 的工作量在协议与状态机（父设计 §4 的判断），画布是"三块同构"的重复劳动，
显示列表用最少代码换到一致性与可测性，且不排斥 B（将来加渲染器即可）。

## 5. 共用坐标与图元

### 5.1 归一化坐标

所有绘制器只在 `(u, v) ∈ [0,1]²` 里工作，**v 向上**（与数学坐标一致），由渲染器负责翻成屏幕像素。
三个视图各给自己的变换，全部引用 git 里已有的约定：

| 视图 | u | v | 说明 |
| --- | --- | --- | --- |
| LIVE | `x/65535` | `1 − y/65535` | `x,y` 已过 `apply_flip(..., flip='y')`（C14）；四角与十字由渲染器画 |
| LOOP | `tick/31` | `1 − contour/1023` | `contour` 是 `y[15:6]`（C1）；叠加 8 条音高档 |
| 波表 | `i/1023` | `(1 + sample)/2` | `sample` 归一化到 −1..+1（C15） |

### 5.2 显示列表图元

绘制器返回一个 `Drawing`：**有序的图元列表**，每个图元只带归一化坐标、颜色语义标签与层号（layer）：

| 图元 | 字段 | 用途 |
| --- | --- | --- |
| `Path` | `points: [(u,v)]`, `closed`, `width`, `color_key` | 轨迹、曲线、轮廓 |
| `Band` | `u0,u1,v0,v1`, `color_key`, `label` | 8 条音高档、播放头区间 |
| `Marker` | `u,v`, `shape`, `label` | 光标点、四角参考、当前 tick |
| `Text` | `u,v`, `text`, `anchor` | 轴标签、音名（G3…C5） |
| `Grid` | `n_u, n_v` | 十字、tick 网格 |

`color_key` 是**语义名**（`track0..track3`、`live`、`bands`、`grid`、`warn`），渲染器映射到具体颜色；
这样主题/色盲友好只需换一张表，不动绘制器。

### 5.3 三条实现规则

1. **绘制器不许 import tkinter**。它只接受数据、返回 `Drawing`。渲染器是唯一碰 Tk 的地方。
2. **渲染器按 tag 分组重画**：`live`（每帧）、`loop_live`（每帧）、`static`（只在数据变化时）。
   LOOP 的已录轨属于 `static`，播放头与正在录的线属于 `loop_live`。
3. **坐标断言用显示列表，不用像素**：测试直接断言"有 8 个 Band、第 3 个标签是 C4、Path 的 v 落在那条带里"。

## 6. LOOP 滚动视图

### 6.1 内容

- 横轴 32 tick（u = tick/31），每 tick 一格；纵轴 8 条音高档（G3/A3/C4/D4/E4/G4/A4/C5，C3）。
- **本次会话录过的轨**：每轨一条 `Path`（从它提交时的 32 个轮廓值来），颜色 `trackN`，画在 `static` 层。
- **正在录的那一轨**：随遥测帧实时追加 `Path` 的末端点（`loop_live` 层），手离开感应区时**断开**
  （`engaged=0` → 该 tick 不画点），于是空档当场可见。
- **播放头**：一条竖线 `Marker`，按 6.2 的相位前进。
- 顶部显示当前轨、覆盖率（已捕获非零 tick 数 / 32）、以及"盲录中：听不到其它轨"。

### 6.2 相位（本设计的第一个待验证点）

硬件没有明确的 loop tick 读回。两条路，**先验证再选**：

1. **验证**：`0xF8` 页 1/页 2 是否暴露当前 tick 或 `loop_tick_m`。有 → 直接用，相位天然准确。
2. **没有就用锚定**：在"发布完成"那一刻（`loop_active_valid` 由 0→1，或 `0x38` bit0 完成后第一次 PLAY）
   记 `t0`，之后相位 `= ((now − t0) / 4.000 s) mod 1`，用单调时钟（`time.monotonic()`）累加。
   - 漂移预算：主机时钟与 48 kHz 的相对误差按 1e-4 估，**每 4 秒偏 0.4 ms ≈ 0.003 tick**；5 分钟演示累计
     约 0.24 tick（≈30 ms），画面上是"提前/落后不到一格"。
   - 界面因此提供**"重新对齐"**按钮（下一次经过 0 位时重锚），并在连续 10 分钟以上时提示可能不同步。
   - **绝不在未对齐时假装对齐**（反目标 §2.3）。

### 6.3 为什么滚动值得做

盲录时操作者需要知道"我现在在循环的哪一段"。静态 32 格只能事后看；滚动版能让操作者**跟着已有曲线走**，
这就是没有 overdub 时的替代品。

## 7. 辅助录制工作流

### 7.1 状态机

```
idle ──选轨/预设──> ready ──倒计时 3s──> arming ──0x18──> capturing
capturing ──0x38 bit4 置位──> captured ──读 32 个样本──> analysing
analysing ──覆盖<30 且重试<2──> ready（自动重录，注明原因）
analysing ──覆盖≥30──> reviewed（显示撞音提示，等操作者确认）
reviewed ──0x28──> committing ──0x38 bit0──> publishing ──0x04=4 到边界──> rolled
rolled ──下一轨──> ready
```

每一步都写 JSONL（父设计 §9），因此"这一版片段"= 位流 sha + 预设 + 命令日志。

### 7.2 覆盖门禁（提交前，硬性）

- 读 `0x34` 32 次（C4）→ 数 `!= 0` 的样本数 `nz`。
- `nz ≥ 30`：通过。
- `nz < 30`：**不提交**，回到 ready 自动重录（最多 2 次），并在画布上把缺口标成 `warn` 色。
- 三次都失败：停下，给出诊断——读 `0xEC` 两次（帧计数在涨 = 传感器活）、`0xDC raw_x`、`0xE0 raw_z`
  （`< 30000` = 手在 engage 阈值内）。这条正是 `host-tools-and-gui-controls.md` §9.3 的判据。

### 7.3 撞音检查（提交前，建议性）

- 从 32 个轮廓值估计这一轨用到的**音级集合**。轮廓是 `y[15:6]`，而硬件把 y 折成 8 个音之一；
  **y → 音号的映射必须先从 DP 里读出来**（见 §10 待办），这是本设计唯一"实现前必须考证"的事实。
- 与本次会话其它轨的音级集合比较，给出三类提示：
  - **同音区同音级**（两条轨都在 C4 一带）→ "会和 track N 撞在一起，建议换音区"；
  - **相邻二度**（C4+D4 持续并存）→ "会有二度摩擦"；
  - **三全音**（C4+F#? —— 本 ROM 无 F#，实际只会出现在 G3+ C#? 不存在；因此三全音提示实际不会触发，
    保留规则以便换音表时不失效）。
- 提示**不阻止**提交（反目标 §2.3）。

### 7.4 每轨音色

提交后可以为该轨单独套一套九个参数（父设计 §6 的预设）。界面上是"轨 N 的预设"下拉，
默认继承当前全局预设。注意 `0x84 level≥2` 的削顶风险（C13）：超过 2 轨时给增益预算提示。

## 9. 验收

**无界面（自动，pytest）**

1. 坐标：LIVE 变换在 `(0,0)→(0,1)`、`(65535,65535)→(1,0)`；`flip='y'` 改变 v 而不改 u（对照 `cursor_view.py`）。
2. 绘制器：给定 32 个轮廓值 → `Drawing` 含 32 个点、8 个 `Band`、标签序列 == `["G3","A3","C4","D4","E4","G4","A4","C5"]`。
3. 覆盖门禁：`nz=29` → 拒绝且 `retry` 计数 +1；`nz=3` 连续三次 → 进入诊断分支并读出三个诊断寄存器。
4. 撞音：两轨同带 → 产生 `warn` 图元与建议文案；不同带 → 无 `warn`。
5. 相位：给定 `t0` 与假时钟，`t0+4.0` → `u≈0`，`t0+2.0` → `u≈0.5`；漂移按 §6.2 预算断言。
6. 状态机非法序列（未 captured 就 commit、arm 中切页）→ 拒绝且不发帧。

**板上（人工，记录）**

7. 录一轨：倒计时可见、覆盖读数与脚本 `contour has N/32` 一致、提交后 `0x38` bit0 置位。
8. 画布上的轨曲线与该轨提交时的 32 个值逐点一致（同一份数据两个消费者）。
9. 播放头与听感：在 4 秒循环上，竖线经过某一 tick 时听到的音符与曲线一致（人耳，记一次）。
10. 重录一轨（`PREPARE_RECORD` 覆盖同名轨）后，其它轨曲线仍在（C7）。

## 10. 留给计划的事

1. **y → 音号映射的考证**（阻塞 §7.3）：从 DP/commit 路径读出 `y[15:6]` 到 8 个音号的换算，
   并写一个对拍测试（喂同一组轮廓，硬件提交出的音符与主机预测一致）。
2. `0xF8` 页 1/页 2 是否暴露 tick（阻塞 §6.2 的选择）。
3. 模块与文件清单（预期：`canvas/mapping.py`、`canvas/primitives.py`、`canvas/render_tk.py`、
   `views/live_painter.py`、`views/loop_painter.py`、`views/wave_painter.py`、`session/record_flow.py`）。
4. 每个任务的测试与顺序；与既有脚本（`board_stage2_loop.ps1`）的对照验收。
5. 帧率与重绘策略（LOOP 20–30 Hz，静态层只在数据变化时重画）。

## 11. 我替你定的（可推翻）

1. 显示列表用**语义色名**而不是 RGB（换主题不动绘制器）。
2. 覆盖门禁阈值 **30/32**（留 2 格容忍偶发丢帧）。
3. 自动重录最多 **2 次**，第 3 次停下并给诊断。
4. 撞音只在**提交前**提示，不阻止。
5. 相位先锚定 + 可重对齐，不追求硬件级同步。
6. 三块画布放在三个标签页里，同一时刻只显示一块（用户选的"各自独立"指画布实例独立，不是同屏并列）。

## 12. 风险

| 风险 | 对策 |
| --- | --- |
| 相位漂移让滚动看起来"抢拍" | 锚定 + 重对齐按钮 + 10 分钟后提示；不确定就标"未对齐" |
| y→音号映射未考证 | 放在计划第一个任务，没考证完不写 §7.3 |
| 30 Hz 重画 Tk 卡顿 | 分层 tag、只重画 `loop_live`、静态层缓存 |
| 覆盖门禁误杀（手很快但有效） | 阈值 30 留余量；三次失败先诊断再让人决定是否强行提交 |
| 每轨预设导致削顶（C13） | 增益预算提示；`level≥2` 且轨数 >2 时警告 |
