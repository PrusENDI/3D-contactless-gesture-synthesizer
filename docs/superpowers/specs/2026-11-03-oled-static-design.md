# OLED 静态图显示（小设计）

> 日期：2026-11-03　状态：**待批准**（批准后才写计划 / 动手）
> 起因：赛题 3b 要求"基于 FPGA 硬件逻辑实时生成可视化反馈"。板上无 LED、无屏，
> 唯一可行的是**一块 SPI/I2C 小 OLED**。本设计只做最小形态：**显示一张不变的图**。
> 依据：`docs/HANDOFF.md`、`docs/host-tools-and-gui-controls.md` §9、
> 最近一次构建 `live_dbg`（CLS 10824/11520、BSRAM 34/56、DSP 28/28、worst −3.447 ns、Fmax 62.7 MHz）。

---

## 1. 意图与为什么

演示需要一个**由 FPGA 自己驱动**的视觉输出。PC 画布再多也不算这一条，因为赛题写的是"FPGA 硬件逻辑实时生成"。
"静态图"是最小可交付：上电把一张 128×64 单色位图写进屏的显存，之后 FPGA 完全空闲。
它先把"FPGA 能驱动屏"这件事变成事实，之后想加李萨如/波形才有地基。

## 2. 目标 / 非目标

**目标**
1. 上电后屏上出现一张**固定的 128×64 单色图**（logo/字/李萨如静帧），不闪、不刷新。
2. 资源上限：**≤ 200 LUT、1 BSRAM、0 DSP**，**不新增乘法**。
3. 加入后 **worst 不得低于 −3.6 ns**（基线 −3.447），否则本功能判定为"放不下"。

**非目标（v1 不做）**
- 不做动画/李萨如/波形/频谱（那是下一版，成本在"刷屏 FSM"，不在 SPI）。
- 不做运行时换图（换图 = 换位流里的 BSRAM 初始化；加"图上传通道"是另一个功能）。
- 不做中文字库/多字体（图是预先栅格化的位图）。
- 不做亮度调节、不读屏（SSD1306 回读不可靠且不需要）。

## 3. 约束（实测/代码，非估计）

| # | 事实 | 来源 |
| --- | --- | --- |
| C1 | 器件现在是 CLS 10824/11520（**剩 696**）、BSRAM 34/56（**剩 22**）、DSP **28/28 满** | `live_dbg` 构建 |
| C2 | 器件是**布局受限**而非逻辑受限：P2b 只加 52 CLS 就全局退化 0.7 ns | `docs/progress-2026-11-01.md` |
| C3 | 128×64 单色 = **8192 bit**，一块 18 Kbit BSRAM 装得下 | 屏规格 |
| C4 | SSD1306 自带 1 KB 显存，"写一次"就保持；不需要持续刷新 | 屏规格 |
| C5 | 一帧 1 KB @1 MHz SPI = **8.2 ms**，静态图无所谓速度 | 计算 |
| C6 | 8192 bit 用 LUT 拼 ROM 要 ~2000 LUT → **直接把器件压垮**，必须用 BSRAM | C1 |
| C7 | 新逻辑若不加区域约束，会去挤音频链/UART 的锥（C2） | 同上 |

## 4. 方案（三种，选 A）

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| **A（选定）1 BSRAM 存图 + 写一次 + 区域约束** | 图在 BSRAM 里当 ROM；上电后 FSM 把 8 页 × 128 列推给屏，然后停机 | 资源最省（~190 LUT / 1 BSRAM / 0 DSP）；**代价是需要一次 floorplan** |
| B LUT ROM 存图 | 不用 BSRAM | 8192 bit 的 LUT ROM ≈ 2000 LUT，C1 只剩 696 → **不可行** |
| C I2C 版 | 2 根线，协议更慢 | LUT 相近（~150），但每字节要 ACK 握手，FSM 略复杂；屏若只支持 I2C 才选它 |

**A 的理由**：BSRAM 有 22 块闲置而 CLS 只剩 696，这个设计**必须把数据放进 BSRAM**；静态图不需要带宽。

### 4.1 接口：**已确认 7 针 SPI**（2026-11-03 用户确认）

屏已确认：**0.96 英寸、128×64、SSD1306**。接口取决于模块的针数：

| 针数 | 接口 | 本设计 |
| --- | --- | --- |
| **4 针**（VCC/GND/SCL/SDA） | 只有 I2C，地址 `0x3C`（个别 `0x3D`），模块自带上拉 | **主路径**：I2C 字节机 |
| 7 针（GND/VCC/D0/D1/RES/DC/CS） | SPI 或 I2C 可选 | 备用：SPI 字节机（§5.1 的版本） |

I2C 主路径的具体数字：

- 速率 **400 kHz**（快速模式），一帧 1 KB + 开销 ≈ `1024×9 / 400k ≈ 23 ms`，静态图无所谓。
- 每次传输：`START` → `addr<<1|0` = `0x78` → 控制字节（`0x00` = 命令流，`0x40` = 数据流）→ 数据… → `STOP`。
- 初始化命令与 §5.1 的表**完全相同**，只是外面套 I2C 帧（一条控制字节 `0x00` 后接多条命令）。
- 引脚只需 **2 根**（SCL/SDA）+ 可选 RES；SDA 需要上拉（4 针模块板上已有）。
- I2C 字节机：START/STOP 生成、移位输出、第 9 拍采样 ACK、位计数 ≈ **140 LUT**（比 SPI 略多，但少 3 根引脚）。

## 5. 设计

### 5.1 结构

```
host/oled_image.py    PNG/PGM ──> artifacts/oled/<name>.mem   (1024 字节, 8 页 × 128 列, 每字节 1 列 8 行)
                                     │
rtl/v2_oled_static.sv  ┌────────────┴─────────────┐
                       │  图 ROM (1 BSRAM)        │
                       │  初始化序列 ROM (~16 条) │
                       │  刷屏 FSM: page 0..7, col 0..127 │
                       │  SPI 字节机 (≈1 MHz)      │
                       └──────────────────────────┘
                        sck / mosi / cs_n / dc / res_n  (5 根)
```

- **像素顺序**：SSD1306 的页寻址，每字节 = 同一列上 8 个纵向像素，**bit0 在最上**。
- **写一页的序列**：`0xB0|page`（页地址）→ `0x00|(col&0x0F)`、`0x10|(col>>4)`（列地址）→ 128 个数据字节。
  8 页共 **8×131 = 1048 次字节传输**，@1 MHz ≈ **8.4 ms**，上电后一次。
- **初始化**：`0xAE`（关显示）→ `0xD5 0x80`（时钟）→ `0xA8 0x3F`（复用率 1/64）→ `0xD3 0x00`（偏移）
  → `0x40`（起始行）→ `0x8D 0x14`（电荷泵开）→ `0x20 0x00`（水平寻址）/ 或页寻址 `0x20 0x02`
  → `0xA1`（段重映射）→ `0xC8`（COM 反向）→ `0xDA 0x12`→ `0x81 0x7F`（对比度）→ `0xD9 0xF1`
  → `0xDB 0x40` → `0xA4`（显示 RAM 内容）→ `0xA6`（正常）→ `0xAF`（开显示）。
  **具体值在计划里按实际屏型号核对**（见 §10）。
- **空闲**：刷完一页/一帧后 FSM 回到 IDLE，不再产生任何翻转（省电、也不扰时序）。

### 5.2 时钟与跨域

- SPI 用**慢使能**（从 100 MHz 分频出 ~1 MHz 的 `spi_ce`），**不新增时钟域**，避免 CDC 与 STA 复杂化。
- 与其它逻辑的唯一接口是：`start`（上电复位后由一个小计数器给一次）、`busy`、`done`。
  没有数据通路，所以**不会成为任何现有锥的一部分**。

### 5.3 区域约束（这条决定时序成败）

给 `v2_oled_static` 及其实例加一个布局区域，放在**远离音频链、UART、波表**的一角：

```tcl
# 计划里按实际 floorplan 校准坐标；GW5A-25 的 CLS 网格约 80×32
INS_LOC -module u_v2/u_oled -region <x0> <y0> <x1> <y1>
```

若不做这一步，预期 worst 从 −3.447 掉到 −3.8…−4.0（C2 的经验）；做了应保持在 −3.5…−3.6。

### 5.4 资源预算

| 模块 | LUT | BSRAM | DSP |
| --- | --- | --- | --- |
| 图 ROM | 0 | 1 | 0 |
| 初始化序列 ROM | ~40 | 0 | 0 |
| 刷屏 FSM（页/列计数 + 命令/数据选择） | ~60 | 0 | 0 |
| SPI 字节机（分频 + 移位 + 位计数） | ~90 | 0 | 0 |
| **合计** | **~190**（≈120 CLS） | **1** | **0** |

## 6. 验收

**无界面（自动）**
1. `host/oled_image.py --selftest`：给定一张 8×8 测试图，输出字节数 == 64/8×… 逐位与参考一致；
   bit0 在最上、页优先排列。
2. `tb/tb_oled_static.sv`：把 `sck/mosi/cs_n/dc` 解成字节流，断言
   ①初始化命令序列与表逐字相同；②每页开头是 `0xB0|page` 与两条列地址；
   ③一帧数据字节数 == 1024，且第 n 个数据字节 == 图 ROM 的第 n 字节；
   ④刷完后 `busy` 落 0 且不再有 `sck` 翻转。
3. `gate.py --compile` 0/0、`sim.py` 13/4、既有全部 tb 不回归。

**板上（人工）**
4. 上电后屏上出现图；`0xB0` 仍是 `0x5A5A0003`。
5. 构建对比：`CLS ≤ 基线+150`、**worst ≥ −3.6 ns**、`dsp` 仍 28/28、`bsram` 34→35。
6. 音频不受影响：LIVE 敲一下、PLAY 放一段，声音与加屏之前一致（听感 + 若可用 GAO 抓 `i2s_sample`）。

## 7. 风险

| 风险 | 对策 |
| --- | --- |
| 布局挤压导致时序退化超线 | 区域约束；仍超则判定"放不下"并回退（本设计不削任何现有功能） |
| 屏不是 SSD1306（SH1106 有 2 列偏移 / 1.3" 屏常见） | 计划第一步就核对型号；偏移量做成参数 |
| 屏是 4 针 I2C 版本 | **已是主路径**（§4.1），SPI 版本反而要改 |
| 引脚冲突（板上有 SPI flash / PSRAM 复用脚） | 计划里先查原理图，再定 `IO_LOC` |
| 对比度/上电顺序不对导致"黑屏" | 初始化表按型号手册逐条核对；先做"全白填充"测试，再换真图 |

## 8. 我替你定的（可推翻）

1. **BSRAM 存图**（C6 逼出来的，不是偏好）。
2. **SPI 而非 I2C**（少一次握手、时序好证）；若屏只支持 I2C 再换。
3. **写一次、永不刷新**（静态图的全部意义）。
4. **图编译进位流**，不做运行时上传通道。
5. 资源与时间预算按 §5.4 / §6.5 的硬线执行，超线就回退。

## 9. 留给计划的事

1. **屏型号与分辨率**（SSD1306 128×64？SH1106？I2C 还是 SPI？）——**这是唯一的阻塞项**。
2. **5 根引脚**的具体位置（查板上排针与复用，避免 SPI flash/PSRAM 脚）。
3. 初始化命令表按实际型号定稿；`host/oled_image.py` 的输入格式（PNG/PGM/纯文本）。
4. `INS_LOC` 区域坐标的实测校准（先构建一次看占用，再定区域）。
5. 与在建的 `minor_arp` 改动**分开两轮**：先验收音阶，再上 OLED，保证因果干净。
