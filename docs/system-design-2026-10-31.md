# MGC3130 手势合成器：系统设计总览（2026-10-31）

本文是**唯一入口**：把音色（波表）、LIVE（演奏）、LOOP（循环）三条链路合成一份。
逐条细节与取舍理由见各节末尾的代码/文档指针。

平台：Tang Primer 25K，GW5A-LV25MG121NES
（23040 LUT / 11520 CLS / 23280 REG / 56 BSRAM；当前 CLS 11029 = 95.7%）
时钟：50 MHz 输入 → PLL 80 MHz 系统时钟；音频 48 kHz；传感实测 138 Hz。
音乐网格：8 小节 × 16 tick = **128 tick**；`samples_per_tick = 720000/BPM`
（120 BPM → 6000 采样 = 125 ms/ tick，一圈 **16 s**；100 BPM → 19.2 s）。

---

## 1. 系统图

```
                 ┌──────────────────── FPGA (GW5A-25K) ────────────────────┐
 MGC3130 ─I2C─▶ 读取器 → 校准 → 光标(α/限速/冻结) ─┬─▶ LIVE 步进琶音 ─┐    │
  138 Hz                                          ├─▶ 轮廓 RAM ─▶ Potts ─┼─▶ 声部×32 ─▶ FX ─▶ I2S
                                                  └─▶ 遥测 22 B ──┐     │
                                                                   │     │
  波表 A/B/C (3×2×1024×16) ────────────────────────────────────────┼─────┘
        ▲                                                          ▼
        └────────── UART 1 Mbaud ◀──────────── PC ────────────────▶
                     ① 录轨迹  ② 弧长相位解算  ③ 分块下发/CRC/APPLY

> 波表目前只接 `WT_PLAY → I2S`（单振荡器查表）；把它接到「声部×32」属于**阶段 1.5**，今天的 LIVE 用的是引擎内置波形。
```

三条链路共用：**光标**（滤波后的 x/y/z）、**音高坐标**（§2）、**声部与 I2S**。
区别只在"谁决定音高、谁决定何时发声、音色从哪来"。

| 链路 | 决定音高 | 决定时机 | 音色 | 延迟 |
| --- | --- | --- | --- | --- |
| 音色（阶段 0） | 固定测试音符 | 无（持续音） | **波表** | 无 |
| LIVE（阶段 1） | 每 tick 的 y | 每 tick | **引擎内置波形**（波表未接入） | ≤1 tick |
| 阶段 1.5（未开始） | 同 LIVE | 同 LIVE | **波表接入声部**（先单声部，再 32 声部） | 同 LIVE |
| LOOP（阶段 2） | Potts 分段 | 事件表 | 波表 | 离线 |

## 2. 共用坐标

### 2.1 音高

**Y 全量程 0..65535，1 半音 = 3855 counts**，只落 A 小调五声 G3..C5：

| 音 | 中心 c_k | 门限（最近邻，相邻中心中点） |
| --- | --- | --- |
| 55 G3 | 0 | — |
| 57 A3 | 7710 | 3855 |
| 60 C4 | 19275 | 13493 |
| 62 D4 | 26985 | 23130 |
| 64 E4 | 34695 | 30840 |
| 67 G4 | 46260 | 40478 |
| 69 A4 | 53970 | 50115 |
| 72 C5 | 65535 | 59753 |

（板上 `map_axis()` 只做 `+32768`，没有 PC 那层 0.648 压缩；本文以全量程为准，
PC 参考需同步。）

### 2.2 时间

`v2_tick_gen`：`samples_per_tick = 720000/BPM`，BPM 60..240（契约，`[31:16]`，默认 120），
越界由 UART 拒收，写入后重置 tick。128 tick = 一圈。

### 2.3 门控

**只用 Z 距离门（`cursor_engaged`）**，不做接触门、不做弓向门。接触/弓向已由用户排除。

## 3. 阶段 0：音色 = 波表

### 3.1 链路

```
手划一次 → 板上遥测上行 cursor x/y/z → PC 弧长相位解算成 1024 点
        → CRC + APPLY 下发 → 板上按音符速率查表发声
```

**上行已存在**：遥测帧带 `cursor_x/y/z`（各 16 bit），22 B/帧，速率由 `TLM_CONTROL` 控制。

### 3.2 板上改动（三处，约 +10 LUT、0 DSP、0 BSRAM）

| # | 位置 | 改动 |
| --- | --- | --- |
| 1 | `v2_wt_playback` | 相位 26→32 bit；`phase += increment`；`index = phase[31:22]` |
| 2 | 顶层 | 测试音符 = `THRESHOLDS[7:0]`；`0` 保持旧 46.875 Hz 行为 |
| 3 | 顶层 | `WT_SELECT[1:0]` 选表 A/B/C |

音符→增量复用现成的 `v2_note_increment_rom`（语义正是 `f/48000 × 2^32`）：

| 音 | increment | 频率 | 周期 |
| --- | --- | --- | --- |
| 55 | 17,537,476 | 195.99 Hz | 244.9 采样 |
| 64 | 29,494,575 | 329.63 Hz | 145.6 采样 |
| 69 | 39,370,534 | 440.00 Hz | 109.09 采样 |
| 72 | 46,819,719 | 523.25 Hz | 91.8 采样 |

上传/校验链路已完成（3 表 × 2 bank、CRC16/CCITT-FALSE、版本三方匹配、
APPLY 只在 idle 或 loop 边界切换；`52009f8` 板上 1024 点读回连过三轮）。

### 3.3 上位机解算（`tools/wavetable_from_capture.py`）

| 步骤 | 规定 |
| --- | --- |
| 平滑 | 每轴 5 帧中值 + IIR 0.35（**先平滑再积分**） |
| 弧长 | `ds = |Δ(x,y)|`；`ds < 40 counts` 记 0（≈3 倍抖动，抑制静止漂移） |
| 相位 | `φ_i = s_i / s_N` |
| 幅度 | **y**（音高轴）；按 φ 重采样 1024 点，线性插值 |
| 后处理 | 去 DC（`|mean|<1 LSB`）、峰值归一 0.9 FS、限带 32 谐波 |
| 输出 | 1024 × int16，首点 = φ0 |

`--phase arc|time|x`，默认 `arc`（速度无关，形状被斜率改写）；`--axis y`。

### 3.4 验收

1. 正弦表 + 音符 69 → 周期 109.09 采样 ±0.5%（GAO 抓 I2S）；
2. 音符 55/64/72 → 244.9/145.6/91.8 采样 ±0.5%；
3. A 表与 B 表上传不同波形 → 抓到的波形不同（排除"内部振荡器"）；
4. idle 时 APPLY 无爆音（相邻样本差 < 10% FS）；
5. `THRESHOLDS[7:0]=0` 仍为 46.875 Hz（旧用例不回归）；
6. 解算器：同一 capture 两次逐字节一致；`|mean|<1`；峰值 0.9 FS ±1 LSB；>32 次谐波 < −60 dBFS。

## 4. 阶段 1：LIVE 步进琶音

### 4.1 规则

```
每个 tick_pulse：NOTE_OFF(上一个) + NOTE_ON(当前 y 的最近邻音级)
```

- 音高相同也重发（步进琶音的"重复敲"），严格 **1 音/tick**（120 BPM → 8 音/秒）；
- 手 = 音高选择器，节奏由 tick 提供；永不冷场；
- gate 落（手离开感应区）时不发新音，并发一次 NOTE_OFF；
- 卡音保护：2 s 无事件强制 NOTE_OFF。

### 4.2 关键修正

| 现状问题 | 修正 |
| --- | --- |
| `tick` 接的是 `sample_index`（48 kHz 计数），`MIN_EVENT_TICKS=4` 等于 83 µs，实际只有帧率 7.2 ms 节流 | 换成 `v2_tick_gen` |
| 事件 tick 字段写 `sample_index[7:0]`（5.3 ms 回绕） | 写 7 bit 音乐 tick |
| `REVOICE` 打包新音高，声部引擎按新音高找声部 → 恒不匹配、静默丢弃 | LIVE 改发 `NOTE_OFF` + `NOTE_ON`，不动声部引擎 |
| `bad_frame` 挡住 `active && !gate`，NOTE_OFF 分支是死码 → 卡音 | 只看 gate 电平 + 超时兜底 |
| `map_note` 的 7 个边界与线性音高不一致（宽度 2/1/2/1/3/2/1/5 半音） | 换 §2.1 的表 |

### 4.3 验收

1. 128 tick 内 128 个 NOTE_ON，间隔恒为 1 tick；
2. y 固定 32 tick → 32 个同音高事件（不是 1 个长音）；
3. y 线性上升的 128 tick → 音高单调，恰好经过 8 个音级；
4. NOTE_ON 之后手移出感应区，≤1 tick 内收到 NOTE_OFF；
5. 1 Hz 正弦手势录 8 小节 → ≥8 个音且音高单调跟随。

## 5. 阶段 2：LOOP 定长轮廓 + Potts

### 5.1 录制

`MODE=RECORD` → 等下一个 `tick==0` → 连续 128 个 tick 写 `y[i]` 与 `valid[i]`（1 BSRAM）。
**只录轮廓，不录事件**，RECORD 期静音。未录满退出则丢弃。

### 5.2 COMMIT

```
0x28 COMMIT
  → PREPARE（active → shadow，等 write_ready）
  → CLEAR_TRACK(lead)
  → Potts（128 tick 轮廓 → 12–17 个音，硬上限 32）
  → 事件写 shadow 的 lead 轨
  → COMMIT_REQUEST → 下一个 loop 边界翻 bank
```

### 5.3 Potts

```
min Σ ((y − c_k) >> 6)² + λ·段数     s.t. 段长 ≥ 4 tick，c_k ∈ §2.1
```

- 音级 5 → 8（`note(k)` 补 55/69/72，收尾判据 `d==4` → `d==7`）；
- λ 放 `THRESHOLDS[31:16]`，默认 21600（= PC 的 λ=6，单位 1 半音² = 3600 LSB）；
- 板级 `HORIZON=32`，形态待定（见 §7）。

### 5.4 验收

1. 录满 128 tick 后 `contour_full=1`；中途退出丢弃；
2. COMMIT 后 PLAY 的事件集 = Potts 输出（4–32 个/圈），每圈相同；
3. 1 Hz 正弦录 8 小节 → ≥8 个音且音高单调跟随；
4. 连续两圈事件 tick 集合一致且都在 0..127。

## 6. 接口

| 资源 | 说明 |
| --- | --- |
| CSR `0x04 MODE` | LIVE / RECORD / PLAY（现成枚举） |
| CSR `0x08 BPM` | 60..240，`[31:16]`，默认 120 |
| CSR `0x28 COMMIT` | 触发 §5.2 序列 |
| CSR `0x30 THRESHOLDS` | `[7:0]` = 测试音符（阶段 0）；`[31:16]` = λ（阶段 2） |
| CSR `0x60..0x7C` | 波表上传：SELECT / INDEX / DATA / LENGTH / CRC / VERSION / APPLY / STATUS |
| UART 上行 | 22 B 遥测帧，带 `cursor_x/y/z`、序列号、flags |
| 事件契约 | 96 bit，`[94:91]` 类型、`[90:88]` 轨、`[87:80]` tick、`[71:64]` 音符、`[63:56]` 力度 |

LIVE 事件**不入** loop store（每轨只有 32 槽）；store 只装 Potts 结果。

## 10. 决策记录（为什么这样选）

| 决定 | 理由 |
| --- | --- |
| LIVE 用 C（每 tick 强制一音），不用 B（帧级即时起音） | 可听性优先；C 不冷场、实现最简；代价是起音 ≤1 tick 而非 ≤7 ms，验收口径随之改为"≤1 tick" |
| 门控只做 Z 距离门 | 用户明确排除接触发声；LIVE 要连续，也不需要运动门 |
| 音高用 Y 全量程（3855 counts/半音） | 免一个乘法器；分辨率比 PC 的 2498 更高；PC 侧同步 |
| LIVE 用 OFF+ON 替代 REVOICE | 现有 REVOICE 语义与声部引擎不匹配（恒丢），改事件编码比改 32 声部引擎风险小 |
| LOOP 只录轮廓、定长 128 tick、一圈一录 | store 每轨仅 32 槽；定长消除叠录/覆盖语义；波形质量由 Potts 而非原始演奏决定 |
| 波表由上位机解算 | 板上限带 32 谐波需要 FFT，CLS 只剩 491，不可行 |
| 相位用弧长（默认） | 速度无关；副作用是陡峭段被拉长，故保留 `--phase x/time` 开关 |
| 幅度取 y | 与音高轴一致，手感直观 |
